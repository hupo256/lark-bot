# 变异测试（aven 2026-10-24：bot 兼顾健壮与效率）

## 它回答什么

单测回答「这次改动有没有弄坏已经被测的行为」；它答不了「哪些行为根本没人测」。变异测试回答后一个问题：把一处代码故意改坏，看测试能不能发现。发现不了（**存活**）= 那行代码改错了也不会有任何测试报红。

10-24 抽样 80 个变异点，有 36 个存活，其中 29 个是真缺口（建任务丢正文、重启后同一消息重复入队、终检误报 HEAD 漂移、回执结算等），已补测。

## 工具：`scripts/mutate.mjs`

| 用法 | 什么时候用 |
|---|---|
| `node scripts/mutate.mjs --diff <基线>` | **合并进运行分支前必跑**：只扫相对基线新增 / 改动的 lib 行。有未豁免的存活就退出 1 |
| `node scripts/mutate.mjs --files lib/a.mjs,lib/b.mjs` | 给一个模块系统补测时扫它的全部变异点 |
| `node scripts/mutate.mjs --sample 80 --seed 7` | 全 lib 随机抽样摸底 |

- 算子：`===` ↔ `!==`、`&&` ↔ `||`、`>` → `>=`、`<` → `<=`、`>=` → `>`、`<=` → `<`、`return true` ↔ `return false`。只认代码位置，字符串 / 模板文字 / 注释里的不算；`import` 行和纯 `console.*` 日志行不算。同一行的每一处都算一个变异点。
- **不碰本目录**：bot 直接跑本目录的代码。每路变异都在临时 worktree（HEAD + 本目录未提交的改动）里注入，跑完删掉。
- **效率**：每个变异只跑受影响的测试（复用 `test-affected.mjs` 的 import 反查），并且先跑直接 import 被改模块的测试，被抓到就不再跑间接的；存活的才跑完全部相关测试。默认按核数最多 3 路、每路测试并发 2（`--lanes` 可调），8 核机器不会被打满。参考：一个 46 个变异点的模块 3 路约 1 分钟。
- 先跑一次未变异的基线，基线红就不跑（`MUTATE_DEBUG=1` 看测试输出）。

## 存活了怎么办

1. **真缺口**：补测试钉住那行代码的**正确业务行为**（不是为了杀变异写空壳）。按仓库约定写成已有 it 里的 `runSteps` 新段或 `eachCase` 新行，不新增 it（体量棘轮）。补完对那个变异点复跑，确认被抓到。
2. **等价变异**（任何可达输入下行为都不变，例如两个时间戳精确相等才有区别、映射表值不可能为假）或**只影响展示且无业务含义**：登记进 `scripts/mutation-accepted.json`：

   ```json
   { "file": "lib/x.mjs", "code": "<该行 trim 后的完整文本>", "op": "|| → &&", "reason": "为什么不必测" }
   ```

   按「文件 + 代码行文本 + 算子」匹配，行号漂移不影响；代码行改了就自动失效，要重新判断。原因必须写清，不写「不重要」。
3. 发现**原代码本身有 bug**（正确行为和实现不一致）：不要把 bug 写进测试，按出错处理原则先分类再修。

## 在验证分层里的位置

| 层 | 跑什么 | 耗时 |
|---|---|---|
| 改的过程中 | `node scripts/test-affected.mjs` | 几秒 |
| 合并进运行分支前 | `node scripts/test-all.mjs` + `node scripts/mutate.mjs --diff <运行分支>` | 十几秒 + 按改动量，通常 1–3 分钟 |
| bot 重启前 | 排空重启自动全量单测（**不跑变异**，保持重启快） | 约 11 秒 |

自修工单（`lib/lark-self-fix.mjs`）改 bot 代码时同样要过 `--diff HEAD`。
