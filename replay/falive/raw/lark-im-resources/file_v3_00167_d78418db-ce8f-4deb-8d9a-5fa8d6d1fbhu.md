# 示例：登录功能点（范本）

> 用「纯模板」填好的一份范本，PM 照此口径仿写其他功能点。下半部分是 AI 读取这份 PRD 后会自动展开的自测用例清单（PM 不用写，用来反向检查 PRD 够不够具体）。

### FN-LOGIN-001 账密登录

- 优先级：P0
- 入口与路径：路由 `/login`；未登录访问任意页也会跳到此页
- 前置条件：存在正常账号 `qa_user01` / `Test@1234`（普通用户）；存在已锁定账号 `locked_user`；当前未登录

**页面元素**

| 元素 | 类型 | 定位 | 默认状态 |
| --- | --- | --- | --- |
| 账号输入框 | input | `data-testid="login-username"` | 空，占位「请输入账号」 |
| 密码输入框 | input(password) | `data-testid="login-password"` | 空，占位「请输入密码」 |
| 登录按钮 | button | 文案「登录」，`data-testid="login-submit"` | 两框空时置灰禁点 |
| 忘记密码 | link | 文案「忘记密码？」 | 可点 |

**操作流程**

1. 进入 `/login`
2. 输入账号、密码
3. 点「登录」

**验收标准（AC）**

- AC-01（P0）：【Given】输正确账密 `qa_user01/Test@1234`【When】点「登录」【Then】≤ 1s 跳 `/home`，右上角显示 `qa_user01`，localStorage 存在 `token`
- AC-02（P0）：【Given】账号对、密码错【When】点「登录」【Then】停留 `/login`，Toast「账号或密码错误」，不存 token
- AC-03（P0）：【Given】两框任一为空【When】观察登录按钮【Then】按钮置灰不可点
- AC-04（P1）：【Given】用 `locked_user`【When】点「登录」【Then】Toast「账号已锁定，请 15 分钟后重试」
- AC-05（P1）：【Given】未登录访问 `/order/123`【When】跳到登录并登录成功【Then】自动回到 `/order/123`
- AC-06（P2）：【Given】请求超 300ms 未返【When】点「登录」【Then】按钮转 loading 且禁点，不重复提交

**输入与校验**

| 字段 | 必填 | 规则 | 合法样例 | 非法样例 | 非法时提示 |
| --- | --- | --- | --- | --- | --- |
| 账号 | 是 | 4–20 位字母/数字 | `qa_user01` | `ab`、`a@#` | 账号为 4–20 位字母或数字 |
| 密码 | 是 | 8–20 位含字母+数字 | `Test@1234` | `123` | 密码需 8–20 位且含字母与数字 |

**异常 / 边界场景**

- EX-01：【触发】连续快点登录 3 次【预期】只发 1 次请求，不重复登录
- EX-02：【触发】登录请求返 500【预期】Toast「网络异常，请稍后重试」，页面不白屏
- EX-03：【触发】密码框粘贴 `<script>alert(1)</script>`【预期】按普通字符处理，不执行脚本

**接口依赖**：`POST /api/auth/login`（详细写法见「用法与说明」的接口依赖模板）

**非功能要求**：登录请求 P95 < 800ms；页面在 375px 宽不横向滚动

**不在本功能范围内**：「记住我」、第三方登录、短信验证码登录

**关联**：设计稿 [登录画板](https://…)；依赖用户中心提供账号
