# 主播录播列表 API 对接文档

> 面向：嗨聊（HiChat）联调 / 前端开发  
> 相关：[B2B-04 直播录制开发文档](./B2B-04-live-record.md)、模块总文档 [11-嗨聊对接 11.23 / 11.35 / 11.36](../doc/live/live-接口与业务说明/11-嗨聊对接.md)  
> 代码：`app/http/live/ctrl/CHiChatProgram.php` → `LLiveRecordTask` → `TLiveRecordTask`

---

## 一、概览

按**嗨聊主播 ID** 查询该主播的直播录像（回放）列表。录像来自嗨聊调用 `liveRoomRecord` 派发的录制任务（见第六节），录制完成后自动出现在列表里。

同一份数据提供两种翻页方式，按页面交互二选一：

| 接口 | 翻页方式 | 适用场景 |
|---|---|---|
| `getHiChatUidRecordVideo` | page 分页，固定每页 20 条，返回总数 / 总页数 | 需要页码、跳页的列表页 |
| `getHiChatUidRecordVideoCursor` | 游标翻页，每页 1~20 条，不返回总数 | 下滑自动加载更多（推荐） |

两个接口的可见范围、排序、单条字段完全相同，只是翻页结构不同。

---

## 二、通用约定

| 项目 | 约定 |
|---|---|
| 路径 | `/api/hi_chat_program/{接口名}`；路径比对忽略大小写和下划线，`/api/HiChatProgram/{接口名}` 等价 |
| 请求方式 | 推荐 **GET**（参数放 query）。用 POST 时参数必须放在 body 里，不要「query 带参数 + body 为空」 |
| 签名 / 登录 | **不需要**验签，不需要登录 Token，不需要 `X-Site-Platform` 请求头 |
| 渠道号 | **必须带**：参数 `channel_code`（或请求头里的渠道号）。取不到渠道号时直接返回空列表，不报错。渠道号只用来判断请求是否有效，**不参与筛选**，列表只按 `hiChatUid` 查 |
| 响应包体 | 明文 JSON：`{ "msg": "...", "code": 0, "data": {...} }`，**不加密、没有 `sec` 字段** |
| 业务码 | `code = 0` 成功；`code ≥ 1` 失败（一般为 1） |
| 参数错误 | 缺 `hiChatUid`、或数字参数传了非数字（如 `hiChatUid=abc`）→ **HTTP 状态码 418**。这类错误由框架直接返回，不走上面的包体，请按 HTTP 状态码判断，不要依赖响应体格式 |
| 时间字段 | Unix 时间戳（秒） |
| 缓存 | 服务端缓存 60 秒，新录好的回放最多晚 60 秒出现在列表里 |

## 三、接口一：page 分页

### `GET /api/hi_chat_program/getHiChatUidRecordVideo`

**请求参数**

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `hiChatUid` | int | 是 | — | 嗨聊主播 ID |
| `page` | int | 否 | 1 | 页码，从 1 开始 |
| `channel_code` | string | 是* | `''` | 渠道号（*不传不会报错，但会直接返回空，见第二节） |

每页条数固定 20，不接受 `per_page`。

**返回 `data`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `total` | int | 回放**总条数** |
| `per_page` | int | 每页条数（固定 20） |
| `current_page` | int | 当前页码 |
| `last_page` | int | 总页数 |
| `data` | array | 本页回放列表，单条字段见[第五节](#五单条回放字段) |

**取不到渠道号时**：`data` 为空数组 `[]`（注意不是上面的分页对象，客户端要兼容）。

**返回示例**

```json
{
  "msg": "操作成功",
  "code": 0,
  "data": {
    "total": 21,
    "per_page": 20,
    "current_page": 2,
    "last_page": 2,
    "data": [
      {
        "id": 4501,
        "record_task_id": 9123,
        "hiChatUid": 880012,
        "live_id": 77790,
        "title": "周末行情复盘",
        "thumb": "https://cdn.example.com/upload/live/77790.jpg",
        "animated_thumb": "",
        "pull": "https://vod.example.com/xxx/playlist_eof.m3u8?t=6A0B1C2D&rlimit=3&us=1a2b3c4d&sign=0123456789abcdef0123456789abcdef",
        "finish_time": 1791291600
      }
    ]
  }
}
```

## 四、接口二：游标翻页（推荐用于下滑加载）

### `GET /api/hi_chat_program/getHiChatUidRecordVideoCursor`

**请求参数**

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `hiChatUid` | int | 是 | — | 嗨聊主播 ID |
| `last_id` | int | 否 | 0 | 上一次返回的 `next_cursor`；不传或 0 = 第一页 |
| `per_page` | int | 否 | 20 | 每页条数；小于 1 按 1、大于 20 按 20 处理 |
| `channel_code` | string | 是* | `''` | 渠道号（同上） |

**返回 `data`**

| 字段 | 类型 | 说明 |
|---|---|---|
| `list` | array | 本页回放列表，单条字段见[第五节](#五单条回放字段) |
| `next_cursor` | int | 下一页游标，下次请求原样作为 `last_id` 传回；**0 = 没有更多了** |

**取不到渠道号时**：`{ "list": [], "next_cursor": 0 }`。

**返回示例**

```json
{
  "msg": "操作成功",
  "code": 0,
  "data": {
    "list": [
      {
        "id": 4501,
        "record_task_id": 9123,
        "hiChatUid": 880012,
        "live_id": 77790,
        "title": "周末行情复盘",
        "thumb": "https://cdn.example.com/upload/live/77790.jpg",
        "animated_thumb": "",
        "pull": "https://vod.example.com/xxx/playlist_eof.m3u8?t=6A0B1C2D&rlimit=3&us=1a2b3c4d&sign=0123456789abcdef0123456789abcdef",
        "finish_time": 1791291600
      }
    ],
    "next_cursor": 4501
  }
}
```

**翻页流程**

1. 第一页：不传 `last_id`（或传 0）。
2. 返回的 `next_cursor` 不为 0 → 滑到底时带 `last_id = next_cursor` 请求下一页。
3. `next_cursor = 0` → 已经到底，停止加载。

**注意**

- `id` **不保证随时间递增**（多段录像合并后的那条，`id` 可能比之后录的还大）。客户端不要按 `id` 排序、也不要拿 `id` 比较新旧，只把 `next_cursor` 原样传回。
- 作为游标的那条回放如果在两次请求之间被删除，下一页会返回空列表、`next_cursor = 0`（当作到底）。下拉刷新从第一页重新拉即可。

## 五、单条回放字段

两个接口的列表元素字段相同：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 回放视频 ID（游标翻页用的就是它） |
| `record_task_id` | int | 录制任务 ID（同一场直播派发一次录制就是一个任务） |
| `hiChatUid` | int | 嗨聊主播 ID |
| `live_id` | int | 直播间 ID |
| `title` | string | 直播间标题（取直播间**当前**标题，主播之后改了标题，回放的标题也跟着变） |
| `thumb` | string | 直播间封面完整地址（同上，取当前封面） |
| `animated_thumb` | string | 直播间动态封面（webp）完整地址；没有时为空字符串 |
| `pull` | string | 回放播放地址（m3u8），**带时效签名**，见第七节 |
| `finish_time` | int | 录制结束时间 = 录制开始时刻 + 视频时长（Unix 秒） |

## 六、列表里会出现哪些回放

**来源**：嗨聊调用 `POST /api/hi_third_user/liveRoomRecord`（参数 `recordList: [{ "liveId": 直播间ID, "hiChatUid": 嗨聊主播ID }]`）派发录制任务，服务端定时发起录制。同一直播间 5 分钟内重复派发只算一次。

**同时满足以下条件才会出现在列表里**：

- 录制任务已完成或已停止（录制中、等待中的不出现）；
- 录像在云点播上**未过期**（过期后自动从列表消失）；
- 有可播放的地址；
- 不在「多段合并」过程中（见下）。

**多段录像合并**：直播中途断流重推，一场直播会录成多段。关播后系统会把多段合并成一条：

- 合并开始前，各段可能以多条回放出现；
- 合并进行中，这场直播的回放**暂时全部不出现**；
- 合并完成后，只剩一条完整回放，其余分段从列表消失。

合并在关播后需要等一段时间才会开始（末段落库后有 5～30 分钟的稳定期），所以一场直播的完整回放通常在关播后几分钟到半小时内出现。

**排序**：按录制任务创建时间倒序（新录的在前），同一时刻按 `id` 倒序。两个接口都不支持自定义排序。

## 七、播放地址 `pull` 的时效与限制

`pull` 是带腾讯云点播防盗链签名的地址，格式 `{m3u8 地址}?t=…&rlimit=3&us=…&sign=…`：

| 限制 | 说明 |
|---|---|
| 有效期 | 生成时刻起 N 秒内有效，N 取后台推拉流设置里的「腾讯云直播回放地址有效时间」，**未配置时为 180 秒** |
| 播放 IP 数 | `rlimit=3`：同一个地址最多允许 3 个不同 IP 播放 |
| 缓存影响 | 列表缓存 60 秒，缓存期内同一主播同一页返回的是**同一个签名地址**：拿到时剩余有效期可能比 N 少最多 60 秒，并且这段时间内所有请求方共用这 3 个 IP 名额 |

**客户端建议**：

- 不要持久化 `pull`，每次播放前用列表接口取最新地址；
- 播放报 403 / 地址过期时，重新请求列表（或刷新当前页）拿新地址再播。

## 八、错误与边界汇总

| 情况 | 结果 |
|---|---|
| 缺 `hiChatUid` | HTTP 418（参数错误） |
| `hiChatUid` / `page` / `last_id` / `per_page` 传非数字 | HTTP 418 |
| 取不到渠道号 | `code = 0`；page 版 `data = []`，游标版 `{ "list": [], "next_cursor": 0 }` |
| `hiChatUid` 不存在，或该主播没有回放 | `code = 0`；page 版 `total = 0`、`data = []`，游标版 `list = []`、`next_cursor = 0` |
| page 超过总页数 | `code = 0`，`data` 为空数组 |
| 游标对应的回放已被删除 | `code = 0`，`list = []`、`next_cursor = 0` |
| `per_page` 超出 1~20 | 自动收敛到 1 或 20，不报错 |

## 九、调用示例

```bash
# page 分页：第 1 页
curl 'https://{域名}/api/hi_chat_program/getHiChatUidRecordVideo?hiChatUid=880012&page=1&channel_code=hc'

# 游标翻页：第一页，每页 10 条
curl 'https://{域名}/api/hi_chat_program/getHiChatUidRecordVideoCursor?hiChatUid=880012&per_page=10&channel_code=hc'

# 游标翻页：下一页（last_id = 上次返回的 next_cursor）
curl 'https://{域名}/api/hi_chat_program/getHiChatUidRecordVideoCursor?hiChatUid=880012&per_page=10&last_id=4501&channel_code=hc'
```

`channel_code` 换成实际对接的渠道号。
