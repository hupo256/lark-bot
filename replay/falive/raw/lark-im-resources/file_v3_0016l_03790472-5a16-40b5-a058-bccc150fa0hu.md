# 任务中心迁移 Go：前端接入与核对清单（16 项）

更新日期：2026-10-20

用途：供前端、直播端及 H5 负责人逐项核对接入情况，并与后端联合验收。本文说明当前接口和接入要求，不代表运行环境已经部署或真实积分已经验收。

## 1. 接入前先明确

- Go 与 HiChat 共用原数据库，继续使用原任务配置和完成记录。前端不需要创建任务、迁移配置或修改数据库。
- 任务的 `id`、`taskCode`、`taskType`、`period`、`points`、`params` 均以任务列表返回值为准，不写死任务 ID、奖励或周期，不根据中文名称或 `FIRST` 字样判断周期。
- 前端主动调用 `complete` 的任务仅按本清单接入：进房、阅读、分享、互动。其他任务走原业务成功触发、观看统计或服务端回调，不额外申报。这里是前端接入约束，不表示后端对其他所有类型都设置了同样的拒绝规则。
- 本文只覆盖截图中的 16 项 HiChat 积分任务，不是 `/bbsv2/member/noviceTask` 的固定四项社区新手任务，也不是 PHP 旧直播任务。不能把不同任务系统的 ID 和状态混用。
- 同一次操作不要同时调用 Java 和 Go 的任务完成接口。共库时 Java 写入的记录也会显示在 Go 列表中，因此仅看到“已完成”不能证明操作已由 Go 处理。

## 2. 16 项任务的前端分工

| 序号 | 任务 | taskType | 前端接入动作 | 是否额外调用 complete |
|---|---|---|---|---|
| 1 | 首次进入直播间 | `FIRST_LIVE` | 本人加入房间获得服务端成功确认后，查询并申报对应未完成任务 | 是 |
| 2 | 登录／注册 | `LOGIN_REGISTER` | 使用 Go 登录／注册流程；成功建立登录态后刷新任务和积分 | 否，Go 成功流程已有触发 |
| 3 | 首次进入 FameEX | `FIRST_CLICK_FAMEEX` | 接入取票、绑定提示及真实 redirect 流程；成功跳转或返回时刷新 | 否，Go redirect 成功后触发 |
| 4 | 首次充值 FameEX | `FIRST_RECHARGE_FAMEEX` | 正常进入充值流程，返回后刷新任务及积分 | 否，由 FameEX 服务端回调 |
| 5 | 首次交易 FameEX | `FIRST_TRADE_FAMEEX` | 正常进入交易流程，返回后刷新任务及积分 | 否，由 FameEX 服务端回调 |
| 6 | 文章评论 | 沿用原库返回的实际类型，不按名称硬编码 | 沿用原文章评论业务；社区类型由服务端回调同步，前端在业务成功／返回后刷新 | 社区类型不额外申报 |
| 7 | 每日发布广场帖子 | `DAILY_PUBLISH_SQUARE_POST` | 正常发布帖子，业务成功／返回任务中心后刷新 | 否，由社区服务端回调 |
| 8 | 广场帖子阅读 | `SQUARE_POST_READ` | 满足原客户端阅读完成条件后，查询并申报对应未完成任务 | 是 |
| 9 | 广场帖子回复评论 | `SQUARE_POST_REPLY_COMMENT` | 正常提交回复／评论，业务成功／返回后刷新 | 否，由社区服务端回调 |
| 10 | 关注主播 | `FOLLOW_ANCHOR` | 使用 Go 对应关注接口，关注成功后刷新；目标使用 HiChat 身份 | 否，新增关注成功后触发 |
| 11 | 分享直播间／群聊 | `SHARE_LIVE_ROOM_OR_GROUP_CHAT` | 满足原客户端分享成功条件后，查询并申报对应未完成任务 | 是 |

| 13 | 观看 5 分钟 | `WATCH_LIVE_DURATION` | 持续上报有效观看统计；具体门槛读取任务 params | 否，Go 累计并判定 |
| 14 | 观看 30 分钟 | `WATCH_LIVE_DURATION` | 复用同一套观看统计，不另外启动任务专用计时器 | 否，Go 累计并判定 |
| 15 | 观看 60 分钟 | `WATCH_LIVE_DURATION` | 复用同一套观看统计，不在本地到时后直接申报完成 | 否，Go 累计并判定 |
| 16 | 直播间互动 | `FIRST_LIVE_ACTION` | 本人符合原业务定义的互动获得服务端成功确认后，查询并申报 | 是 |

## 3. 接口地址与登录凭证

### 3.1 接口列表

以下均为 Go 应用收到的路径。网关前缀由部署负责人确认；如果外部使用 `/go-api`，外部任务列表地址就是 `/go-api/api/points/task/list`，由网关剥离 `/go-api` 后转给 Go。不要重复拼前缀，也不要继续把已切流任务请求指向 Java。

| 方法 | Go 应用路径 | 用途／参数 |
|---|---|---|
| GET | `/api/points/task/list` | 查询任务及完成状态，无请求体 |
| POST | `/api/points/task/complete` | 普通申报，JSON：`{"taskId":123}` |
| GET | `/api/points/task/myPoints?pageNum=1&pageSize=20` | 查询积分余额和流水第一页 |
| PUT | `/api/video/statistics/{groupId}` | 观看统计，无请求体，使用 HiChat groupId |
| POST | `/api/b2b/follow` | 关注，JSON：`{"targetId":123}`，使用目标 HiChat member ID |
| DELETE | `/api/b2b/follow` | 取消关注，JSON：`{"targetId":123}`，不触发关注奖励 |
| GET | `/api/member/profile/my` | 任务中心所需会员／FameEX 资料子集，携带 X-HC-UID |
| GET | `/api/fameEx/oneTimeToken/v2` | 获取 FameEX 一次性票据，可携带 country_code 头 |
| POST | `/api/fameEx/redirect/{action}` | 通过 X-One-Time-Token 传票，action 和请求参数沿用原协议 |
| GET | `/api/thirdConfigManage/getStatus` | 行情展示开关，不是 FameEX 总开关或任务完成接口 |

示例中的 `123` 仅为格式示例，不是真实任务、用户或房间配置。

### 3.2 请求头与身份

- 普通受保护接口使用当前账号的登录凭证。Go 登录返回的 `token` 使用 `Authorization: hiApp <token>`；继续使用 Java 会员凭证时，按原协议拼接 `hichat_token_head + hichat_token`，例如 `hiApp` 与 JWT 直接拼接。优先复用项目现有登录请求封装。
- 不把 PHP `live_token` 或 FameEX 一次性票据作为任务接口的登录凭证。不要使用社区 uid、Live sender 或房间号替代 HiChat 会员身份。
- 保留原 `X-Version`、`X-Device-Type`、`Accept-Language`；`X-HC-UID` 是设备标识，不是会员 ID。已有 `X-Request-Source` 等业务头也按原协议透传，不自行虚构取值。
- 当前 Go 对观看时长、关注、分享、广场阅读／回复／发帖、邀请任务有 `X-Version >= 3.11.6` 的展示门槛。前端应确认实际兼容版本和请求头，不通过伪造版本绕过适配；缺失／旧版本可能导致任务不显示。
- FameEX redirect 使用取票返回的 `token` 作为 `X-One-Time-Token`。它与 Go 登录接口返回的同名 `token` 不是同一种凭证，需分别管理。
- 浏览器跨域需要网关／服务端允许所需的请求方法和自定义头，尤其是 PUT、DELETE、X-Version、X-Device-Type、X-HC-UID、X-One-Time-Token。遇到预检失败交由后端／运维处理。

## 4. 普通任务如何申报

适用：`FIRST_LIVE`、`SQUARE_POST_READ`、`SHARE_LIVE_ROOM_OR_GROUP_CHAT`、`FIRST_LIVE_ACTION`。

### 4.1 确认真实成功事件

| 事件 | 可以作为申报时机 | 不可以作为申报时机 |
|---|---|---|
| 进房 | 加入房间接口／协议返回成功，账号会话仍一致 | 点击“去完成”、进入路由、页面渲染、仅 WebSocket 建连 |
| 互动 | 本人符合原业务定义的消息／互动获得服务端成功确认 | 输入文字、发送中的乐观消息、发送失败、历史消息、重连补拉、他人消息 |
| 阅读 | 原客户端／产品口径定义的阅读完成事件 | 仅点击任务卡片；自行新增或猜测阅读时长门槛 |
| 分享 | 原客户端／产品口径认可的分享完成事件 | 打开分享面板、分享取消或失败 |

直播侧需明确提供进房成功和互动成功的真实 ACK 来源，可在前端封装为 `onRoomJoined`、`onMessageConfirmed`。这些是建议的本地事件名称，不是新增后端接口。不要自行把关注、送礼等动作全部纳入同一个互动口径。

### 4.2 查询并匹配任务

```http
GET /api/points/task/list
Authorization: hiApp <当前账号的Go登录token>
X-Version: <实际兼容版本>
Accept-Language: <当前语言>
```

任务列表响应的 `data` 直接是数组，不是 `data.items`。以下仅展示主要字段，名称、奖励、ID 和编码均为示例：

```json
{
  "code": 0,
  "msg": "以实际响应为准",
  "data": [
    {
      "id": 123,
      "taskCode": "example_room_task",
      "taskName": "进入直播间",
      "taskType": "FIRST_LIVE",
      "period": "ONCE",
      "points": 20,
      "taskStatus": 0,
      "finishTime": null,
      "params": []
    }
  ],
  "sec": ""
}
```

从列表筛选 `taskType` 与成功事件相同且 `taskStatus == 0` 的全部任务。同一类型的新手／每日任务可能具有不同 ID，不要只取第一条，也不要按名称查找。

### 4.3 发出申报

```http
POST /api/points/task/complete
Authorization: hiApp <当前账号的Go登录token>
Content-Type: application/json

{"taskId":123}
```

- 使用列表中真实的 `id`。字段是 `taskId`，不是 `task_id`；发送 JSON 对象，不是双重编码后的字符串。
- 不传 `memberId`、`points`、`period`，不让前端指定领奖账号或奖励金额。
- 对筛选出的任务逐个申报，控制并发，不重复绑定事件监听器。用户不需要再点击一次“完成”按钮。
- 房间 ID、进房会话标识和 msg_id 可以用于前端事件去重与排错，但不是现有 complete 接口的新增字段。

### 4.4 申报后刷新与失败处理

```text
真实操作成功
  → 记录当前账号会话版本并去重事件
  → 查询 task/list
  → 筛选对应类型的全部未完成任务
  → 逐个 POST task/complete
  → 再次查询 task/list 与 task/myPoints
  → 有限次数延迟刷新，更新任务、总积分和流水
```

- 普通 Go 接口以业务 `code == 0` 判断受理成功，不按 Java 的 `code == 200` 判断。`code == -700` 处理登录失效，`code == -1` 按业务拒绝处理；其他错误按现有错误处理约定展示。不能只看 HTTP 200。
- complete 的 `code=0`、`data=null` 只是异步受理，不保证任务已经写入或积分已经到账。后续业务判断也可能未通过，不能据此直接把卡片标成完成。
- `taskStatus=1` 且 `finishTime` 有值表示完成记录可查询；finishTime 为毫秒时间戳。积分仍需核对 myPoints 的 `totalPoints` 和 `pointsRecordPage`，记录完成不等于外部积分已到账。
- data 已是明文业务数据；sec 如存在，由原公共响应层处理，不要对同一业务数据重复解密或重复应用结果。
- 可立即刷新一次，再按 0.5、1、2、4 秒做有限退避刷新。这是建议的前端策略，不是服务端到账 SLA。到上限仍未同步时保留“处理中／稍后刷新”，不本地加分、不虚构流水、不无限轮询。
- 请求超时／断网且结果未知时，先查任务状态；仍未完成、仍是同一账号和同一周期时，最多补试两次。不要把所有失败都当网络错误重试，也不要跨日重放旧事件。
- 退出登录或切换账号时，清理待处理事件、请求回调和轮询；旧账号的 ACK 不能为新账号申报或覆盖新账号界面。

## 5. 观看 5／30／60 分钟的接入

```http
PUT /api/video/statistics/{实际HiChat群ID}
Authorization: hiApp <当前账号的Go登录token>
X-Device-Type: <原协议约定的真实设备类型>
```

- 无请求体，不上传前端自报的总秒数、任务 ID 或积分数。
- groupId 是 HiChat 群／直播关联 ID，不是 PHP Live 房间号。前端只有 Live 房间号时，先与后端明确映射来源，不能直接替代。
- 沿用实际观看心跳，按每 10 秒一次的节奏接入；当前任务累计每次有效处理增加 10 秒。不要因为页面存在就计时，不高频调用，也不要断网恢复后批量补发心跳。
- 5／30／60 分钟共用一条统计链路，只维护一套有效观看定时器，不为三张任务卡分别上报。实际门槛以 `params` 中 `name=liveDurationMinutes` 的 value 为准，由 Go 判断是否达标。
- 停止观看、离开房间、退出登录／切换账号时停止对应上报。后台播放是否算有效观看沿用原播放器规则，不自行扩大奖励口径。
- 正确传递 X-Device-Type。缺失或不符合原设备类型范围可能被忽略；服务端还会检查群关系和观看资格，因此收到受理成功不代表本次一定增加任务时长。
- 游客统计不能作为会员任务领奖链路。不要将游客统计接口的成功当作当前会员任务完成。
- 达到本地预计时长后，只刷新任务列表和积分，不另行调用 complete；跨日累计和周期完成状态以服务端为准。

## 6. 自动触发与回调任务的接入

### 6.1 登录、注册、关注、邀请

- 普通登录／注册使用 `/api/auth/login`、`/api/auth/register`；Google 流程使用 `/api/auth/google/login`、`/api/auth/google/register`，登录参数沿用现有账号接口契约。调用其他系统的登录入口不会自动执行 Go 入口中的任务触发。
- 登录／注册成功后建立本账号的正确登录态，再刷新任务及积分，不额外 complete。
- 关注使用 `POST /api/b2b/follow`，JSON 字段为 targetId，值是目标 HiChat member ID，不是未经映射的 Live 主播 ID。重复关注和取消关注不会产生新的关注奖励。
- 邀请链接沿用原邀请参数来源；被邀请人普通注册／Google 注册时按现有契约传 `agent_id`。这是邀请方身份，不是当前账号 ID 或社区 uid，不能随意填默认值。无邀请关系时不传该可选字段。
- 邀请奖励属于邀请方。被邀请人注册成功不代表邀请方页面会自动收到推送；邀请方返回任务中心时重新查询即可，不要在被邀请人客户端替邀请方 complete。

### 6.2 FameEX 入口、充值、交易

1. 从真实 FameEX 业务入口发起流程；需要会员绑定状态时使用 profile 接口，携带设备标识 X-HC-UID。该接口只提供任务中心所需资料子集，不替代完整个人资料接口。
2. 获取新的 oneTimeToken，沿用原 H5 传票协议。取票本身不完成 FIRST_CLICK_FAMEEX，也不要在单纯打开任务中心时自动取票／跳转来刷任务。
3. 按 bindPrompt 处理原绑定流程：0 沿用原流程但不等于已绑定；1 账号不存在；2 有账号未绑定；3 已绑定其他 HiChat。需要手动绑定时使用返回的 manualBindUrl，完成后重新查询状态并获取新票据。
4. redirect 使用 X-One-Time-Token；当前票据有效期 300 秒且只消费一次。过期、已消费或失败后需要重试时，重新取票，不反复使用同一个票据。action 和业务参数沿用原协议。
5. 外层页面和嵌入 H5 内部调用的 API base 都要核对；只切外层任务页，不能保证 H5 redirect 已走 Go。返回的 H5 url 是资源路径，按已确认的可信 H5 origin 解析，不拼 API 的 /go-api 前缀。跳转域名使用实际 HTTPS 白名单。
6. 充值 recharge／跟单 copyTrading 等原流程需要 groupId 时，传真实 HiChat groupId，不用 Live 房间号替代。只有成功取得 redirect 信息才由 Go 触发首次进入任务。
7. 首充和首交易由 FameEX 服务端回调 Go，前端只刷新结果。不能根据页面跳转成功、充值提交或前端展示的交易状态自行 complete。

### 6.3 文章评论、广场发帖和回复评论

- 正常调用现有社区业务接口，不把“提交评论”替换成“申报任务”。等待原业务成功／审核生效条件，完成状态以重新查询为准。
- 继续读取共用原库的配置，前端不需要重新配置文章评论任务，也不通过改 taskType 来适配。
- 社区发奖完成后，由社区服务端通知 Go `/api/discuz/callback/complete_task`。Go 只同步完成记录，不再为同一社区奖励加一次积分。
- 该回调是服务端之间的接口，不是前端接口。前端不得持有或发送社区 Access-Token，不把它写入 JavaScript、移动端包或前端环境变量。
- 业务成功但任务仍未完成时，提交任务 ID／编码、请求 ID、操作时间给后端排查，不通过额外 complete 补状态或手动加分。

## 7. 非前端事项：联调前请对应负责人确认

| 责任方 | 需要确认的事项 |
|---|---|
| 后端／运维 | Go 已部署当前任务接口；外部域名、网关前缀、转发路径和 CORS 配置正确 |
| 社区后端／运维 | 社区完成通知确实发往 Go `/api/discuz/callback/complete_task`，专用 DISCUZ_CALLBACK_TOKEN 与发送端凭据匹配；仅有接收接口不代表发送链路已接通 |
| FameEX 对接方／后端 | 首充和首交易分别回调 Go `/api/fameEx/callback/firstRecharge`、`/api/fameEx/callback/firstTrade`，使用匹配的 POINTS_CALLBACK_TOKEN；与社区凭据分开 |
| 后端 | 原库任务配置、平台归属、模块开关和原表结构可用；共库不等于所有平台的同名任务都相同 |
| 直播／账号后端 | 提供真实进房和互动成功事件、HiChat groupId、目标会员 ID 的来源或映射，避免与 Live／社区 ID 混用 |
