HiChat 推广助理分配机制

用户和访客在什么时候会被分配一个私聊推广助理、按什么规则选人、写了哪些数据，以及助理在线状态、后台配置、日报和清理怎样配合。逻辑主要在 hichat-portal，在线状态由 hichat-im 维护，配置与清理在 hichat-admin，日报在 hichat-crontab。

选谁

后台给群配置的助理名单 + 助理是否在线 + Redis 轮流计数。两种算法：方式 A（在线轮流 → 离线轮流）和方式 B（本群在线 → 默认群在线 → 默认群随机）。

写什么

一条「用户 → 助理」联系人和置顶会话（方式 A 还会以助理名义发欢迎语），外加一条分配日志 major_promote_group_promoter_assign_log。

之后

分配日志进入推广员日报的在线 / 离线配客数；访客好友和超过 30 天的访客定期清理；用户和助理之间不能互相拉黑或删除。

方式 A：在线轮流，全员离线再离线轮流

用于登录用户进入重点推广群，以及注册、登录后分到默认群。同一用户在同一群只分配一次。

步骤说明

  • 1触发点：POST /group/promote/enter（只处理非访客、非助理）；手机 / 邮箱注册、手机密码 / 短信 / 邮箱登录、Google 登录与直接注册、HICHAT 新设备登录（这些分到平台默认群）。
  • 2查 major_promote_group_promoter_assign_log：同一用户在同一群已有记录就跳过。所以登录虽然每次都触发，实际只有第一次生效。
  • 3候选 = 该群在 major_promote_group_promoter_config 配置的助理，按会员 id 去重、升序；名单缓存 hichat:major:promote:group:promoter:config:list:{groupId}，3 小时。
  • 4在线助理里轮流：INCR hichat:promoter:group:assignment:online-turn:{groupId}，选第 (计数 − 1) mod 在线人数 个；选中后再确认一次在线，不在线重选，最多 3 次。
  • 5一个在线的都没有：用 offline-turn:{groupId} 在全部候选里轮流。3 次都没选成而仍有人在线时，本次不分配（没写日志，下次进群再试）。
  • 6助理必须有 promoter_config，否则失败且不写日志。写联系人（用户 → 助理）；按用户语言取多语言欢迎语，以助理名义写入 ums_chat_history；Mongo 会话标记为助理、未读。
  • 7日志：is_guest 为用户是否访客，is_promoter_online 为是否在线轮流选中。

方式 B：本群在线 → 默认群在线 → 默认群随机

用于访客打开推广群链接，以及 Banner 的「默认群助理」素材。不防重复，也不发欢迎语。

步骤说明

  • 1入口：GET /promote/group/getByGroupLink（SLINK，用 X-HC-UID 取访客）、GET /landing/promote/group/getByGroupLink（落地页，用当前登录态，可带 toChatId）；只处理重点推广群。
  • 2先调用 enterPromoteGroup 写进群记录；访客在这一步不分配，登录用户会在这里先按方式 A 分配一次。
  • 3落地页带 toChatId=u{助理id} 时直接用该助理（只要他在任意群有配置）；进入的就是默认群时不分配（Banner 不做这项判断）。
  • 4–6依次：本群在线轮流 → 默认群在线轮流 → 默认群随机一个（不看在线）。和方式 A 共用在线轮流计数；没有离线轮流。
  • 7已是联系人就不再建；否则写联系人和会话，不发欢迎语。每次请求都会写一条分配日志，is_guest 固定为 true，is_promoter_online 为当时真实在线状态。
  • Banner：素材 url 为 AsstUserName=PROMOTER_DEFAULT_GROUP 时，服务端选人并建联，再把 url 换成 AsstUserName={助理 username} 返回。

注意

  • !同一访客每打开一次链接就重新选一次人，可能被加上多个助理；Banner 每拉取一次也会推进轮流计数。
  • !落地页的登录用户会先按方式 A、再按方式 B 各分配一次，可能拿到两个不同的助理。
  • !默认群兜底是随机且不看在线，访客容易分到离线助理。

助理在线状态

「在线」只看 Redis 的在线 Hash：助理连着 WebSocket 且 2 分钟内有活动。

步骤说明

  • 2WS 鉴权（CLI_AUTH）、心跳、收到消息、SYS_ONLINE 时刷新：先看离线锁，有锁就忽略；记录连接到会话 Hash（2 分钟过期），并把当前时间写入在线 Hash。
  • 3从不在线变为在线时，通过 MQ 通知刷新用户的会话列表，用户看到助理上线。
  • 5连接断开：移除该连接，并清掉 2 分钟无活动的连接；一个连接都不剩时移出在线 Hash 并通知会话列表。
  • 7主动登出：移出在线 Hash，设离线锁 hichat:promoter:offline:lock:{id} 5 分钟（期间心跳不会重新上线），记录 last_logout_time。
  • 8admin 每分钟检查在线 Hash，最后活跃超过 2 分钟的移出并通知会话列表。

后台配置、推广员日报与清理

配置决定候选名单和欢迎语；分配日志进入推广员日报；访客好友和访客账号定期清理。

步骤说明

  • 1GET/PUT /group/{groupId}/promoterAssignment：只能配置重点推广群；可选助理为有 promoter_config 且同平台的；保存时整组先删后插，并清掉群 → 助理、助理 → 群两组缓存。
  • 2GET/POST /promote/group/default：按平台写 platform_promoter_default_group。
  • 3POST /promoter、POST /promoter/update/I18n/WelcomeMessage：写 promoter_config，保存时清缓存。新建 PR 助理账号时会自动初始化这份配置。
  • 4每天 04:00 统计前一天：取 is_guest = false 的分配日志，同一（助理, 用户）只算一次，统计日之前配对过的不再算；按 is_promoter_online 分为在线 / 离线配客数。
  • 6每天 05:32，只处理当时不在线的助理：删除其访客联系人——没聊过且添加超过 30 分钟，或最后聊天超过 7 天；联系人和会话两个方向都删。
  • 7每天 03:00，建号超过 30 天的访客置为删除，清掉其所有联系人与会话，并通知相关助理刷新。
  • 访客注册转会员沿用同一个会员 id，访客期间分到的助理联系人保留；用户与助理之间不能互相拉黑或删除。

注意

  • !修改默认群不清 portal 缓存 hichat:promoter:default:group:id:{平台}，最长 3 小时后生效。
  • !群助理名单先删后插且没有事务，中途失败该群会没有助理。
  • !方式 B 写的日志 is_guest 固定为 true，落地页登录用户、Banner 会员的分配不计入日报配客数。
