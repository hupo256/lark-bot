注册

手机、邮箱、Google 三种注册都落到同一组表；admin 不参与注册，只在次日 05:00 读表出报表。

数据落点

  • 2验证码存在 Redis portal:authCode:{手机|邮箱}，180 秒有效。admin 系统工具可以直接生成验证码，也可以设置不过期的全局测试码 portal:test:authCode（传空即删除）。
  • 3ums_member：member_type = 0（USER）、status = 1、is_special = 1。Google 注册以 email 建号（country_calling_code = email）。
  • 4ums_member_extend：register_way 1 手机 / 2 邮箱 / 3 Google，另记着陆页、IP、设备与系统版本、国家城市、系统语言。
  • 5有群链接或市场码时写 ums_promote_group_statistics（只有市场码时 group_link 用默认群）；群有效且同平台时再写 ums_group_member_register_log。市场码按 _ 拆成 market / channel 回写会员表。
  • 6手机注册、邮箱注册、Google 直接注册都会完成 LOGIN_REGISTER：按 admin 配置发积分，同时同步注册到 Discuz。

admin 口径

  • 7每日新增：create_time 在当天且为 USER，或 delete_time 在当天；没有手机和邮箱的视为游客丢弃；按跑批时的状态分为新增 / 删除 × 手机 / 邮箱。
  • 7推广渠道 = group_link[_market][_channel]，查不到归为 other，另有汇总行 all。
  • 7N 日留存（N = 1/3/5/7/30）：D−N 当天注册的 USER + 启用会员里，D 当天有登录日志的人数。
  • 7新增 DAU：当天注册且当天有登录日志或成功发过消息。有效激活：当天成功发消息、关注主播、或非游客观看直播 ≥ 10 秒。
  • 7用户分层：NEW 注册于 [D−2, D]；SUB_NEW 注册于 [D−14, D−3]；REGISTERED_DAY_7 注册于 D−6 当天。

注意

  • !删除分支不限定 member_type：后台建号、Discuz 账号的 phone 存的是流水号，删除时会计入「删除手机用户」。
  • !当天注册、次日 05:00 跑批前就被删除的会员，只计删除不计新增。
  • !新增 DAU 率、激活率的分子要求 status = 启用，分母（新增手机 + 邮箱）不要求。

登录与每日活跃

统计里的「登录」不是登录接口，而是用户当天打开 App 拉取过一次个人资料。

数据落点

  • 2手机密码、短信、邮箱登录都会完成 LOGIN_REGISTER 任务；Google 已绑定账号登录不会。
  • 2推广助理登录时写 ums_member_chat_daily_stats.first_login_time，每天 03:00 汇总成推广员日报。
  • 4GET /member/my 异步记录，10 秒 Redis 锁；写成功后设置 hichat:member:login:log:{id} 到次日 0 点，当天后续请求直接跳过。
  • 4ums_member_login_log：login_count = 之前的行数 + 1（累计登录天数）；continuous_login_count = 昨天有记录则 +1，否则为 1；首条 group_link 取推广归因，没有则为 other，之后沿用上一条。

admin 口径

  • 5N 日留存看注册队列在第 N 天当天是否有登录日志，不是区间内任意一天。
  • 5分层活跃：注册满 14 天，且 [D−14, D] 内登录 ≥ 3 天；消息或直播观看 1–2 次为 ACTIVE，≥ 3 次为 ALWAYS_ACTIVE。
  • 系统工具 POST /system/member/continuousLoginCount 可全表重算连续登录天数（SUPER_ADMIN / DEV）。

注意

  • !DAU / WAU / MAU 不是去重人数：只取 D 当天登录的人，再数他们在 [D−N, D]（N+1 天）内的登录行数。DAU = D 活跃人数 + 其中 D−1 也活跃的人数。
  • !留存代码注释写「时间范围内至少登录一次」，实现是「第 N 天当天登录」。
  • !分层用到的消息和直播次数取全部历史，不是 14 天内；同一人可能同时是 ACTIVE 和 ALWAYS_ACTIVE。

Google 授权登录

首次授权先建一条未绑定的 oauth2 记录，注册后才绑定到会员；已绑定则直接登录。

数据落点

  • 3按 provider = google + 加密后的 sub 查 ums_oauth2；没有记录就先 INSERT（provider_user_id、email 加密，member_id 为空、未绑定）。
  • 5直接注册：建 email 账号、register_way = 3，回写 oauth2 的 member_id 与 bind_status；完成 LOGIN_REGISTER，并走推广归因。
  • 6已绑定：校验 App 登录权限、写设备信息、失败次数清零；set_password_status 为 0 时提示设置密码（1 已设置，2 稍后设置）。推广助理更新首次登录时间；来自 FameEx 时跳转 FameEx。
  • 7直播主登录（isStreamHostLogin）额外签发 b2bToken，存入 hichat:b2b:login:token:{token}。
  • 已登录用户在设置里绑定 Google：写 oauth2，bind_status = true、set_password_status = 1。

admin 口径

  • 会员列表 LEFT JOIN oauth2：账号类型 0 = 无绑定（provider 为空），1 = Google。
  • 统计中 Google 注册用户计入「新增邮箱」；用户分析表注册方式显示 Google。
  • /b2b/** 用 Redis 取 memberId；is_stream_host 为 false 时删除 token 并拒绝；通过后续期 30 分钟。

注意

  • !删除 Gmail 注册用户是物理删除，只删第一条 oauth2 和 ums_member，extend、登录日志等不删。
  • !/b2b/public/** 免鉴权，memberId 直接取自请求体。
  • !授权后未完成注册的 oauth2 记录（member_id 为空）会一直留存。

Discuz 注册（双向）

Discuz 调 admin 建 HiChat 账号；反方向由 portal 在用户完成登录注册任务时同步到 Discuz。

数据落点

  • 2签名串 nickname=…&timestamp=…&username=… 做 HMAC 校验；时间戳为毫秒，前后 5 分钟有效；头像必填，经 hichat-fs 上传。
  • 3username 命中任何未删除会员，直接返回该会员并标记 isExisting = true，不创建、不校验会员类型。
  • 4流水号 DZ + yyyyMMdd + 3 位，Redis 按天自增（1 小时过期，取不到回源数据库最大值）；流水号已存在同样返回已有会员。
  • 5member_type = 4、平台 HICHAT、phone = 加密流水号、country_calling_code = other、固定密码、状态启用；只建记事本，不写 extend 和登录日志。
  • 9每天从 Discuz 拉取发帖、访问的人数与次数，写 stats_daily_discuz_member。

admin 口径

  • Discuz 账号 member_type = 4，不计入新增、留存、分层。

注意

  • !username 撞到普通用户会被当成同一人返回给 Discuz。
  • !HMAC 密钥与 Discuz 会员默认密码硬编码在代码里。
  • !Discuz 账号被删除时会计入日报的「删除手机用户」。

FameEx 授权绑定

FameEx 回调绑定结果：任何结果都推送给 App，只有绑定成功才落库。

数据落点

  • 2请求头 Access-Token 与配置值比对，不一致返回 403。
  • 6bind_status：1 成功、2 冻结、3 无账号、4 已绑定；只有 1 会落库。
  • 7ums_member.fameex_status = 1（RELATED）；register_time（毫秒）有值才写 fameex_register_time；已是 RELATED 直接跳过，首次关联时间不会被覆盖。
  • 8用户分析表展示关联 FameEx、关联时间、首次入金；非 HICHAT 平台隐藏这些字段。

admin 口径

  • CEX 入口注册 UV = fameex_conversion_log 中 type = REGISTER 的去重 member_id，来源限 GROUP / MINI_PROGRAM / ONE_TAP / STREAM_LOBBY。
  • /fameEx/members/appsflyerId 只返回 USER + 启用会员的 AppsFlyer ID。

注意

  • !没有 extend 行的会员（Discuz、后台建号）更新 fameex_register_time 会静默失败。
  • !回调 action 枚举里有 register，但没有对应处理器，调用会返回「当前 action 业务不支持」。

后台管理员登录

后台账号独立于会员体系：失败计数和 token 都放 Redis，新登录会挤掉旧 token。

数据落点

  • 2先按 email、再按 username 查 ums_admin_member（排除已删除），再校验账号状态与平台。
  • 3失败计数 ≥ 6 时，15 分钟内即使密码正确也拒绝；每次失败都把过期时间重置为 15 分钟。
  • 5成功后写 ums_admin_login_log（admin_id、IP、时间），清空失败计数；登录动作另经 BehaviorLog 切面记入后台操作日志。
  • 6JWT 有效 1 小时；Redis 只存最新 token（3 小时）。刷新时剩余有效期超过 30 分钟原样返回，否则签新 token 覆盖；登出删除该 key。
