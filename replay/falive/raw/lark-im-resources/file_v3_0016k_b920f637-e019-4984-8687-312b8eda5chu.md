## 二、Go 账号接口补充对接说明

### 2.1 H-hdr：当前 Go 已实现接口的额外请求头清单

**结论：不能对所有 Go 请求统一要求 `X-HC-UID` 和 `X-Device-Type`，也不能统一删除。**以下按当前已发布至 pre 的 Go 版本 `6c7b68d`，逐项列出应用实际注册的 **55 条入口**：19 条账号 / 验证码、22 条其他前端业务、13 条服务间 / 回调及 1 条健康检查。全局 OPTIONS 预检不另计；本次核对代码和本地测试，未执行 pre 全接口线上回归。

#### 2.1.1 表格约定：通用头、鉴权、额外业务头分开

- 表内使用 **Go 应用路径**。前端经既有 pre 网关调用 `/api/...` 时，外部路径为 `/go-api/api/...`，不要重复加前缀。服务间入口是否对外暴露由网关决定，不能仅因 Go 注册了路由就认定浏览器可调用。
- `Content-Type` 按请求体格式设置；`Accept`、浏览器的 `Origin` 等通用 HTTP 头不逐行重复。`X-Request-ID` 是全局可选追踪头，不是业务必填。
- `Authorization` 单列为“鉴权”，不混入额外头。`Accept-Language` 虽是标准头，但只有部分业务读取，因此在对应行标出。
- **必传**：Go 有缺失 / 格式检查；**条件传**：影响某种业务模式，可能不是缺失即报参数错；**可选**：缺失不会因该请求头直接拒绝，但可能影响返回内容或记录。
- `X-Hc-Uid` 与 `X-HC-UID` 是同一个头的不同大小写；**`X-UID` 是另一个字段，不能混用**。“无”仅指无额外业务请求头，不代表无需参数、鉴权或配置。

| 鉴权标记 | 应如何传 |
|---|---|
| P | 正式 Go 账号会话：`Authorization: hiApp <portal_token>`，`hiApp` 后有一个空格。 |
| M | Go 会员业务鉴权：可使用 P 的 Go token；当前代码也兼容符合其校验规则的 HiChat 会员 token，沿用对应凭证格式。不是 PHP `live_token`。 |
| V | 观看统计鉴权：必须有有效 `Authorization`，在会员会话之外支持符合规则的游客会话；路径带 `guest` 不等于免登录凭证。 |
| — | 不依赖通用 `Authorization`；如有一次性票据、Access-Token 或合作方签名，仍必须按表传。 |

#### 2.1.4 容易误接的必填条件与默认行为

**A. 两个 profile 不是同一个接口。**`/api/auth/profile` 不要求设备头；`/api/member/profile/my` 缺少 `X-HC-UID` 会返回参数错误。后者当前只检查该头存在，不检查非空 UUID 格式；前端仍应传真实非空设备标识，不应利用空值绕过。`X-HC-UID` 不是会员 ID。

**B. `X-Device-Type` 不能套一条统一校验规则。**

- Adjust 采集：缺失、空值、非整数或超出 int32 均拒绝；当前未进一步限制设备枚举，因此 0 / 负数不是因枚举校验被拒绝。
- 两个 FameEX 入口（`/api/member/profile/my`、`/api/fameEx/oneTimeToken/v2`）：缺失或不能解析为 int32 时按未提供处理，不因此直接拒绝。
- FameEX redirect：不传可用；传了非空值但不能解析为 int32 则参数错误。
- 观看统计：普通会员不传时设备值为 0，会被过滤并成功返回而不执行统计；普通会员传非整数会报参数错误。当前允许统计的设备值为 `1、2、3、4、5、6、8、9、17、18、19`，Web 沿用已约定的 `1`。真实游客身份（member_type=5）强制按 18 处理；member_type=3 使用 `{groupId}` 入口直接忽略。这是身份 / 统计过滤，不是只看路径是否包含 guest。

**C. 新版签到使用来源和版本组合。**

- Web：`X-Request-Source: WEB` 直接进入新版签到，不要求再用版本门槛选分支。
- App / Flutter：`X-Request-Source: APP` 或 `FLUTTER`，且 `X-Version` 至少 `3.12.0`。
- 来源缺失或不匹配时，即使单独传较高 `X-Version`，也不会进入新版签到。旧分支仍可查询 / 签到，但不能补签。
- `X-Request-Source` 的值大小写不敏感。`X-Version` 是双方约定的客户端版本，不是浏览器版本或前端构建时间。

**D. 任务列表的版本门槛独立于签到来源。**`WATCH_LIVE_DURATION`、`FOLLOW_ANCHOR`、`SHARE_LIVE_ROOM_OR_GROUP_CHAT`、`SQUARE_POST_READ`、`SQUARE_POST_REPLY_COMMENT`、`DAILY_PUBLISH_SQUARE_POST`、`INVITE_FRIEND` 这些任务类型要求 `X-Version >= 3.11.6` 才可能进入列表；还要满足任务上线时间等业务条件。缺失 / 无法识别版本时会过滤这些类型，不是整个接口报错；`X-Request-Source: WEB` 不能替代这里的版本判断。

**E. 一次性票据不能放进 Authorization。**先通过会员鉴权调用 `/api/fameEx/oneTimeToken/v2`，再把响应中的短期 token 放到 redirect 的 `X-One-Time-Token`。票据可能被消费，失败重试也应重新取票，不在全局请求拦截器里复用它。

**F. 相似名字的字段不能互换。**`country_code` 请求头是 FameEX / 统计链路的地区信息（如 `CN`），不等于短信请求 JSON 中的电话区号；`X-System-Language` 是统计 / 日志系统语言，不等于消费 `Accept-Language` 的展示语言；普通账号登录 JSON 的 `device_type` 与数字型 HTTP 设备头也不是同一参数。

#### 2.1.7 代理头与 CORS：后端能读取，不等于浏览器应主动传

- 短信日志、权益兑换、FameEX profile / 取票的客户端 IP：依次读取 `X-Forwarded-For`、`X-Real-IP`，否则用连接地址。
