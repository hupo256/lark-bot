--------------------------------
一、录播 / 推荐视频（V1–V3 / R2）≠ 主播直播回放
--------------------------------
说明：video/getList 是「用户点播短视频 / 社区视频」，不是主播直播存档回放。
主播直播回放见下文「R3 / 录播存档」新接口。

V1（pre hc 灌点播）
→ 运营/后台在 hc 平台灌几条已审核通过的用户视频（cmf_user_video status=1）。不是代码问题。

V2（video[] 结构）
→ 实际是对象数组，不是字符串 url：
  video: [ { "img": "https://...封面", "video": "https://...播放地址" }, ... ]
- img / video 已拼完整域名
- 播放地址按上传文件扩展名（常见 mp4）；接口本身不强制
- 列表没有独立 duration 字段；没有时长就不显示角标即可
- 同级还有 flie（原始附件）、is_flie_type=1 表示视频

V3（addView）
→ GET/POST /api/video/addView?id=  公开接口，打开播放时调一次即可
- 可不登录（游客也会记一条）；登录则挂当前用户
- id 为空会参数错误

R2（单条详情）
→ 已补公开接口：GET/POST /api/video/getInfo?id=
- 字段口径同列表单条（含 video[] / flie / 封面等）
- 拉最新代码后再接

--------------------------------
二、主播直播回放 / 存档（原 R3）——不要用嗨聊接口
--------------------------------
hi_chat_program/getHiChatUidRecordVideo* 是给嗨聊用的（入参 hiChatUid），直播站前端不要直连。

已新增直播站对外接口（按 live 主播 uid）：

page 分页：
  GET/POST /api/front/anchorRecordList?uid={主播uid}&page=1
  GET/POST /api/preload/anchorRecordList?uid={主播uid}&page=1
  每页固定 20；须带渠道

游标翻页（推荐下滑加载）：
  GET/POST /api/front/anchorRecordListCursor?uid={主播uid}&last_id=0&per_page=20
  GET/POST /api/preload/anchorRecordListCursor?...

单条字段：
  id / record_task_id / uid / hiChatUid / live_id / title / thumb / animated_thumb / pull / finish_time
- pull 为带时效签名的 m3u8，不要长期缓存；过期重新拉列表
- 渠道解不出平台、或主播对该平台不可见 → 空列表
- getRoomInfo 已有 uid，直接拿 uid 调本接口即可；不需要再为 broker 透 hiChatUid 去打嗨聊接口
