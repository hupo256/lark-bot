## 👥 角色与权限（谁能在哪儿做什么）

**一期共 4 类角色**。权限差异**只体现在「能否操作」，不体现在「能否浏览」**——这是从 klive 继承下来的游客模式：**不登录也能把全站看完**。

| 角色        | 怎么识别        | 浏览                                        | 互动（预约 / 送礼 / 留言 / 发帖 / 评论 / 兑换 / 跟单 / 关注） | 进后台                                     |
| --------- | ----------- | ----------------------------------------- | ----------------------------------------- | --------------------------------------- |
| **未登录访客** | 无 token     | ✅ 首页、直播列表、直播间、节目表、新闻、社区广场、主播个人主页 **全部可看** | ❌ 任何写操作**先弹登录**（见 G-04）                   | ❌                                       |
| **登录用户**  | 有效 token    | ✅ 同上                                      | ✅ 全部                                      | ❌                                       |
| **主播**    | 登录用户 + 主播身份 | ✅ 同上                                      | ✅ 同上                                      | ❌（自己的数据看板属 C-3，一期不做）                    |
| **运营**    | falive 后台账号 | —                                         | —                                         | ✅ 配 banner / 推荐位 / 节目表 / 营销视频 / 积分 / 审核 |

**四条关键规则**：

1. **浏览免登录，写操作才要登录。** 未登录点「预约 / 送礼 / 留言 / 发帖 / 兑换 / 跟单 / 关注」→ 先跳登录，**登录成功后自动继续原操作**，不丢上下文（见 G-04）。
2. **未登录访客看不到个人化数据。** 积分总额、签到记录、任务进度、未读消息在未登录时**一律不展示**（不是显示 0、不是显示空态）。
3. **需要登录才能进的页面闭集（与「页面清单」的「需登录=是」列必须一致）**：`/me` 我的、`/me/edit` 资料编辑、`/task` 任务中心、`/task/checkin` 签到补签、`/task/points/history` 积分流水、`/task/exchange` 特权商城、`/chat` 聊天、`/gift` 礼物页、`/copy-trading` 一键跟单 —— 共 **10 个页面（P06~P11、P17、P18、P20、P22）**。**其余全部免登录可看**。
4. **被封禁账号**：Web 与 App 状态必须一致（`FN-USER-003`）。封禁后**受保护操作不可执行**，但历史内容仍可见。

> ⚠️ 技术 AI 注意：**不要给浏览类页面加登录墙**。klive 原站就是匿名可看，加了登录墙属于功能缺陷，会被判不通过。

| **已签到**     | 该日已签到（含正常签到与补签）   | 【待补：颜色/图标】 |
| **未签到（漏签）** | 该日在本周内、在今天之前、且未签到 | 【待补】       |
| **等待签到**    | 该日在本周内、但在今天之后     | 【待补，通常灰显】  |

**周期示意（按周 7 天，跨周重置）**

```
本周（周一 ~ 周日）
 一    二    三   [今天]   五    六    日
已签  漏签  已签   ④      待签  待签  待签
 └──────── 昨天及以前 ────┘   └── 今天及以后 ──┘
        明天变「周一」，整条重置
```

> ⚠️ 两个反例，别做错：① **不要画成整月日历**（klive 是月，HiChat 是周，一期按周）；② **取消/重置发生在周一 00:00**，不是「签到满 7 天」那一刻。

**文案（🔶 参考 HiChat，falive 逐字【待补】）**：「签到成功」「你已累计签到 N 天」「签到失败，请重试」。

**验收标准（AC）**

- AC-01（P0）：【Given】今日未签到【When】点「签到」【Then】`P0+20`，动画反馈，连续天数 +1
- AC-02（P0）：【Given】同日已签到【When】再点签到【Then】被拒提示已签，积分不再增加
- AC-03（P0）：【Given】查看签到进度条【When】观察状态【Then】存在「等待签到/已签到/未签到」三态，**当天在第 4 位**，前三日为已签/未签、后三日为等待签到

**异常 / 边界场景**

- EX-01：【触发】快速连点签到 3 次【预期】只发 1 次请求，只加 1 次积分  
  **不在本功能范围内**：每日曲线增长积分打卡（后期）

### 🔁 一键跟单专章（先读这一段，再看 `FN-PROF-005` / `007` / `008` / `009`）

> 本节依据《一键跟单 API 说明（2026-10-08）》把技术口径翻成产品语言。**技术 AI 请以本节的产品描述为准去实现，接口细节以那份 API 说明为准（本文档不复制字段表）。**

#### 一句话说清这个功能

**falive 不替用户下单。** 用户点「一键跟单」后，falive 只负责把他**免密送进 FameEX 的跟单配置页**；真正的跟单设置（跟多少钱、固定额度还是固定比例、止盈止损）**在 FameEX 完成**。

所以 falive 侧只需做三件事：

1. **把交易员选出来** —— 交易员列表 + 筛选 + 排序
2. **点之前校验够** —— 避免跳过去打不开（白屏/报错体验最差）
3. **把用户免密送过去** —— 用一次性令牌换免密跳转链接

⚠️ **合规红线（G-23）**：这是**金融产品引流**。交易员列表页和跳转入口旁必须有**风险提示**（投资有风险，逐字文案【待补】）；全站**不得出现**「保收益」「稳赚」类承诺性文案（含交易员卡片的收益展示——只展示历史数据，不做成收益承诺的措辞）。

> ✅ **这条结论直接关掉了 C-1 的一半**：一键跟单**不是**「复用 FameEX SDK Web 版」，而是**纯跳转**。C-1 剩下的疑问只针对合约交易本身。

#### 用户看到的完整流程（4 步）

| 步 | 用户做什么         | falive 做什么                     | 用户看到什么                 |
| - | ------------- | ------------------------------ | ---------------------- |
| 1 | 打开一键跟单页       | 拉取**该范围内可见的交易员列表**             | 交易员卡片列表                |
| 2 | 用筛选 / 排序挑人    | 按收益、胜率、跟单人数等筛选排序               | 列表重排、结果条数更新            |
| 3 | 点某个交易员的「一键跟单」 | 校验 → 签发**一次性令牌** → 换**免密跳转链接** | 【待补：直接跳，还是先出中间页】       |
| 4 | （落到 FameEX）   | —                              | FameEX 跟单设置页，**已是登录态** |

#### 交易员卡片要展示什么

| 信息          | 说明             | 用户为什么关心       |
| ----------- | -------------- | ------------- |
| 头像 + 名称     | 交易员在交易所的展示名与头像 | 认人            |
| **月收益率**    | 最近一个月收益率       | 选人的第一指标       |
| **总收益**     | 累计收益金额         | 赚了多少          |
| **胜率**      | 盈利订单占比         | 稳不稳           |
| **跟单人数**    | 当前 / 上限        | 人气；**满了就跟不了** |
| **分润比例**    | 交易员从跟单收益里抽多少   | 成本            |
