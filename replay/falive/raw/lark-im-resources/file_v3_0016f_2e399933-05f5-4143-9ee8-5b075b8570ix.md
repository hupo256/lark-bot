### 1.2 与 Live（PHP）旧接口的差异

- **路径不同**：Live 的账号接口是 `/api/user/NewLogin`、`/api/user/NewRegistered` 等（清单见 [README](./README.md) 第八节），本服务是上表的路径。按规划，第一阶段要改成与 Live 相同的路径，目前还没有对齐。
- **外壳相同**：响应外壳、`sec` 加密方式与 PHP 相同，现有的 PHP 解密代码可以直接用（2.3）。
- **请求验签、请求加密、限频还没有实现**：请求体是明文 JSON，不需要签名头。
- **错误码**：只有 `0`、`-700`、`-1` 三种，靠 `msg` 区分具体原因（第四节）。

## 二、通用约定

### 2.1 请求

- 请求体是 JSON，请求头带 `Content-Type: application/json`。`GET /api/auth/profile` 没有请求体。
- **字段名是蛇形**（`platform_code`、`task_id`）。写错的字段名会被忽略，不会报错；如果它是必填字段，会返回 400「参数错误」（例如把 `platform_code` 写成 `platformCode`）。
- **int64 字段（各种 ID、`expires_in`、`points` 等）收发都是 JSON 数字**。传成字符串（`{"task_id":"3"}`）会返回 400。
- 校验顺序：先解析请求体（不是合法 JSON 时返回 400），再校验登录态（需要登录的接口没登录时返回 -700），最后校验必填字段。
- 服务端超时 10 秒。CORS 允许任意来源，预检请求（OPTIONS）返回 204。

### 2.2 鉴权与登录态

- 注册、登录类接口**同时返回三种凭证**（三端账号开启时）：
  - `token`：portal JWT，请求本服务受保护接口用，默认有效 7 天（`expires_in`，单位秒）。请求时带 `Authorization: hiApp <token>`，`hiApp` 和 token 之间有一个空格。
  - `live_token`：本服务实时向 Live 换来的，给 Live（PHP）接口用。密码登录、注册调 Live 的 `/api/internal/login`（有手机号时）或 `/api/internal/mailLogin`；验证码登录、Google 登录和注册由本服务校验身份后，调 `/api/internal/issueToken` 按用户 ID 签发。Live 不可用时，注册、登录整体返回「外部服务调用失败」。
  - `hichat_token`：本服务签发的嗨聊 token，前缀是 `hichat_token_head`（即 `hiApp`），给嗨聊接口用。
- 三端账号未开启（后端没配齐 Live、Discuz 库等）时，登录只返回 `token`，`live_token` 与 `token` 相同，没有 `hichat_token`；注册等会写三端的接口返回 503。
- 收到 -700 时清掉本地凭证、跳转登录。
- 下表是各操作对已签发凭证的影响：

| 操作 | portal `token` | `hichat_token` |
|---|---|---|
| 修改密码、找回密码、Google 设置密码 | 失效，响应里返回新的 | 失效，响应里返回新的 |
| 注销账号 | 失效 | 失效 |
| 修改资料、绑定手机号或邮箱、绑定或解绑 Google | 不变 | **失效，接口不返回新的**，要用时重新登录获取 |

改密码类接口返回新凭证时，`user_info.platform_code` 固定为 `LIVE_WEB`，嗨聊 token 不带设备号。

### 2.3 响应格式

除 `/health` 外，所有响应都是 PHP 外壳。生产环境：

```json
{"code": 0, "msg": "Operation successful", "sec": "<data 的密文>"}
```

| 字段 | 说明 |
|---|---|
| `code` | 0 成功；-700 登录失效；-1 其他失败 |
| `msg` | 成功固定为 `Operation successful`；失败是错误提示（第四节） |
| `sec` | `data` 的密文。成功时是第三节示例里的「响应 data」；没有数据的接口（返回 `google.protobuf.Empty`）是 `{}`；失败时是 `[]` |
| `data`、`reason` | 只有服务端开了 debug 模式（`server.debug: true`，仅开发环境）才返回：明文 `data`，失败时的错误原因 `reason` |

debug 模式下（开发联调时看到的样子）：

```json
{"code": 0, "msg": "Operation successful", "data": {"points": 10}}
{"code": -1, "msg": "密码错误", "reason": "PASSWORD_INVALID", "data": []}
```

**解密 `sec`**：Base64 解码 → AES-128-ECB 解密（PKCS#7 填充，密钥与 PHP 的 `API_AES_KEY` 相同，向后端要）→ zlib 解压 → JSON。JSON 里的中文、emoji 是 `\uXXXX` 转义，`JSON.parse` 能直接还原。Node 示例：

```js
import { createDecipheriv } from 'node:crypto';
import { inflateSync } from 'node:zlib';

function decryptSec(sec, aesKey) {
  const decipher = createDecipheriv('aes-128-ecb', Buffer.from(aesKey, 'utf8'), null);
  const zipped = Buffer.concat([decipher.update(Buffer.from(sec, 'base64')), decipher.final()]);
  return JSON.parse(inflateSync(zipped).toString('utf8'));
}
```

浏览器里步骤相同，常用 crypto-js（`mode: ECB`、`padding: Pkcs7`）解密，再用 pako 的 `inflate` 解压。

**测试向量**（用来验证解密代码；密钥 `0123456789abcdef` 只用于测试）：本服务把 `{"nickname":"中文😀","user_id":7}` 加密成下面的 `sec`，上面的 Node 示例能还原出原文。

```text
/TLrRDgOY7KfIu4FwzY/eM3CWQVac+2jGvkMA0UzXHKIj3NxDGEG2rfnO5R0zT3iCTiZhDoh+NIjKJgrX7NEpg==
```

**data 里的字段值**：

- 字段名是蛇形，与请求一致。
- **零值字段不输出**：`0`、`""`、`false` 和空对象都会省略（例如未绑定嗨聊时没有 `hichat_id`，`status` 为 0 时没有 `status`）。客户端要把缺失的字段按零值处理。
- 时间字段（`created_at`、`bound_at`、`last_sync_at`）是 RFC 3339 字符串。
- 状态、性别等枚举值是数字，取值见各字段说明。

### 2.4 HTTP 状态码

| HTTP | code | 含义 |
|---|---|---|
| 200 | 0 | 成功 |
| 200 | -700 | 未登录、token 无效或已失效 |
| 200 | -1 | 业务拒绝，提示 `msg` |
| 400 | -1 | 参数缺失、取值非法或请求体无法解析，`msg` 为「参数错误」等 |
| 500、503 | -1 | 服务端错误或三端账号未配置，`msg` 统一为 `Internal server error` |
| 404 | — | 路径或方法不存在，响应体是纯文本 `404 page not found`，没有外壳 |

**服务端永远不会返回 401、406、451**：高防收到这三个状态码会把客户端 IP 拉黑 300 秒。

## 三、接口

下面的「必填」指 proto 里标了 `REQUIRED` 的字段，缺失时返回 400。「失败」列出常见的 `msg`，对应的 HTTP 状态码见第四节。字段的完整说明以 `api/portal/v1/*.proto` 的注释为准。

示例里的「响应 data」是 `sec` 解密后的内容（debug 模式下就是 `data` 字段），HTTP 响应体是 2.3 的外壳。`<portal JWT>`、`<Live token>`、`<嗨聊 JWT>`、`<Google ID token>` 是占位符。

### 3.1 公共结构

**LoginResponse**（登录、Google 登录、Google 注册、修改密码、找回密码、Google 设置密码返回）

| 字段 | 类型 | 说明 |
|---|---|---|
| `token` | string | portal JWT，请求本服务受保护接口用 |
| `live_token` | string | Live token；三端账号未开启时与 `token` 相同 |
| `hichat_token` | string | 嗨聊 token |
| `hichat_token_head` | string | 嗨聊 token 的前缀，固定 `hiApp` |
| `discuz_uid` | int64 | Discuz 用户 ID |
| `expires_in` | int64 | token 有效期，单位秒，默认 604800 |
| `user_info` | UserInfo | 当前用户 |
| `relogin_required` | bool | 只在改密码类接口出现：为 true 时密码已经改好，但新凭证没有签发出来（凭证字段都为空），要让用户用新密码重新登录 |
| `refresh_token`、`is_need_set_password` | — | 目前不返回 |

**UserInfo**

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | int64 | Live 用户 ID |
| `hichat_id` | int64 | 嗨聊用户 ID，未绑定时不返回 |
| `nickname` | string | 昵称 |
| `avatar` | string | 头像 URL |
| `phone` | string | 手机号（不含国家/地区码） |
| `email` | string | 邮箱 |
| `status` | int32 | 0 禁用、1 启用、98 冻结 |
| `platform_code` | string | 登录时传入的平台编码；改密码类接口是 `LIVE_WEB`；修改资料、绑定手机号的响应里不返回 |

LoginResponse 的完整示例（登录、修改密码等接口都是这个结构）：

```json
{
  "token": "<portal JWT>",
  "live_token": "<Live token>",
  "hichat_token": "<嗨聊 JWT>",
  "hichat_token_head": "hiApp",
  "discuz_uid": 30001,
  "expires_in": 604800,
  "user_info": {
    "user_id": 10001,
    "hichat_id": 20001,
    "nickname": "Alice",
    "avatar": "https://cdn.example.com/avatar/10001.png",
    "phone": "13800138000",
    "email": "alice@example.com",
    "status": 1,
    "platform_code": "LIVE_WEB"
  }
}
```

### 3.2 验证码

验证码是 6 位数字，默认 180 秒有效；同一手机号或邮箱 60 秒内不能重发。短信验证码按「`country_code` + 手机号」保存，**发送和使用时 `country_code` 要用同一种写法**（`86` 和 `CN` 不通用）；邮件验证码不区分邮箱大小写。

**校验接口会作废验证码。** 注册、登录、绑定、找回密码会自己校验验证码，不要先调校验接口再提交，否则业务接口会返回「验证码错误或已过期」。校验接口只用于单独确认验证码的场景。验证码输错不会作废，也不限次数。

| 接口 | 请求字段 | 响应 data | 失败 |
|---|---|---|---|
| `POST /api/auth/verification/send` | `phone`（必填，不含国家/地区码）、`country_code`（必填，要在后端的短信国家表里）、`scene`（必填，只记日志） | `{}` | `verification code already sent`、`sms disabled`、`invalid phone`、`unsupported sms country`、`外部服务调用失败` |
| `POST /api/auth/verification/verify` | `phone`、`country_code`、`code`、`scene`（四个都必填，`scene` 未使用） | `{}` | `invalid verification code` |
| `POST /api/auth/verification/email/send` | `email`（必填，不能带显示名）、`scene` | `{}` | 邮箱格式不对 400；`email verification disabled`、`verification code already sent`、`外部服务调用失败` |
| `POST /api/auth/verification/email/verify` | `email`、`code`（都必填） | `{}` | 邮箱格式不对 400；`invalid verification code` |

示例：

```http
POST /api/auth/verification/send
{"phone": "13800138000", "country_code": "86", "scene": "login"}

POST /api/auth/verification/verify
{"phone": "13800138000", "country_code": "86", "code": "123456", "scene": "login"}

POST /api/auth/verification/email/send
{"email": "alice@example.com", "scene": "bind"}

POST /api/auth/verification/email/verify
{"email": "alice@example.com", "code": "123456"}
```

四个接口成功时的响应 data 都是 `{}`。

测试环境可能开了 mock（不真正发送）和固定验证码，以后端配置为准。

### 3.3 注册

**`POST /api/auth/register`**：注册，同时建好 Live、嗨聊、Discuz 三端账号，并返回三种凭证。

| 字段 | 必填 | 说明 |
|---|---|---|
| `phone` | 与 `email` 至少一个 | 手机号（不含国家/地区码）；填了就用它作登录名 |
| `email` | 与 `phone` 至少一个 | 邮箱；没有手机号时用它作登录名 |
| `password` | 是 | 6～72 字节（按 UTF-8 编码后的字节数） |
| `nickname` | 是 | 昵称 |
| `country` | 填手机号时要填 | 国家/地区码，用于保存手机号和校验短信验证码。**注意是 `country`，不是 `country_code`** |
| `otp_code` | 后端开启验证码校验时必填 | 填了手机号时校验短信验证码，否则校验邮件验证码 |
| `platform_code` | 是 | 平台编码 |
| `google_sub`、`google_email`、`country_code` | 否 | 目前不使用 |

请求：

```json
{
  "phone": "13900139000",
  "password": "secret123",
  "nickname": "Bob",
  "country": "86",
  "otp_code": "123456",
  "platform_code": "LIVE_WEB"
}
```

响应 data（**没有 `user_info`**）：

```json
{
  "user_id": 10002,
  "hichat_id": 20002,
  "bind_result": "created",
  "token": "<portal JWT>",
  "live_token": "<Live token>",
  "hichat_token": "<嗨聊 JWT>",
  "hichat_token_head": "hiApp",
  "discuz_uid": 30002,
  "expires_in": 604800
}
```

- 失败：`phone`、`email` 都没填 400；`验证码错误或已过期`、`邮箱验证码错误或已过期`、`用户已存在`、`密码错误`（长度不对）、`外部服务调用失败`；三端账号未配置 503。
- 返回 `外部服务调用失败` 时 Live 账号已经建好，用户下次登录时会补齐嗨聊和 Discuz 账号，不要让用户重新注册。

**`POST /api/auth/google/register`**：用 Google 账号注册，登录名和邮箱都是 Google 邮箱。

| 字段 | 必填 | 说明 |
|---|---|---|
| `id_token` | 是 | Google ID token |
| `platform_code` | 是 | 平台编码 |
| `password` | 否 | 6～72 字节；不填时账号没有密码，之后用 `/api/auth/google/password` 设置 |
| `otp_code` | 否 | 目前不使用：Google 身份由本服务校验，Live token 按用户 ID 签发 |
| `nickname` | 否 | 为空时用 Google 邮箱 @ 前面的部分 |
| `device_id` | 否 | 设备号 |

请求：

```json
{
  "id_token": "<Google ID token>",
  "platform_code": "LIVE_WEB",
  "password": "secret123",
  "device_id": "device-001"
}
```

响应 data（LoginResponse；`user_info` 不带 `phone`，没传 `nickname` 时取邮箱 @ 前面的部分）：

```json
{
  "token": "<portal JWT>",
  "live_token": "<Live token>",
  "hichat_token": "<嗨聊 JWT>",
  "hichat_token_head": "hiApp",
  "discuz_uid": 30003,
  "expires_in": 604800,
  "user_info": {
    "user_id": 10003,
    "hichat_id": 20003,
    "nickname": "alice",
    "email": "alice@gmail.com",
    "status": 1,
    "platform_code": "LIVE_WEB"
  }
}
```

- 失败：`用户名或密码错误`（实际是 Google token 无效）、`Google account already bound`、`Google email already registered`、`外部服务调用失败`（已写入的数据会尽量撤销）；三端账号未配置 503。

### 3.4 登录

**`POST /api/auth/login`**：用手机号、邮箱或登录名登录，同时补齐嗨聊和 Discuz 账号，并返回三种凭证。

| 字段 | 必填 | 说明 |
|---|---|---|
| `username` | 是 | 手机号、邮箱或登录名 |
| `password` | 是 | 密码；带 `otp_code` 时不校验，但仍要传非空值 |
| `platform_code` | 是 | 平台编码 |
| `device_type` | 否 | 设备类型，为空时按 `pc` |
| `otp_code` | 见说明 | 带上时改为验证码登录；后端开启验证码校验时，绑定了手机号的用户必填 |
| `country_code` | 校验短信验证码时要填 | 与发送验证码时的写法相同 |
| `device_id` | 否 | 目前不使用 |

密码登录：

```json
{
  "username": "13800138000",
  "password": "secret123",
  "platform_code": "LIVE_WEB",
  "device_type": "pc"
}
```

验证码登录（`password` 随便填一个非空值）：

```json
{
  "username": "13800138000",
  "password": "-",
  "otp_code": "123456",
  "country_code": "86",
  "platform_code": "LIVE_WEB"
}
```

响应 data：LoginResponse，见 3.1 的完整示例。三端账号未开启时只有 portal 凭证（`live_token` 与 `token` 相同，没有 `hichat_token`、`discuz_uid`、`hichat_id`，`expires_in` 固定 604800）：

```json
{
  "token": "<portal JWT>",
  "live_token": "<portal JWT>",
  "expires_in": 604800,
  "user_info": {
    "user_id": 10001,
    "nickname": "Alice",
    "avatar": "https://cdn.example.com/avatar/10001.png",
    "phone": "13800138000",
    "email": "alice@example.com",
    "status": 1,
    "platform_code": "LIVE_WEB"
  }
}
```

- 失败：`用户不存在`、`密码错误`、`用户已被禁用`、`验证码错误或已过期`、`外部服务调用失败`（开通嗨聊、Discuz 或向 Live 换 token 失败）。
- 验证码登录时，验证码由本服务校验（账号绑定了手机号时校验短信验证码，没有手机号时校验邮件验证码，校验成功后作废），不校验也不使用 `password`；`live_token` 由 Live 的 `/api/internal/issueToken` 按用户 ID 签发。验证码错误时直接返回「验证码错误或已过期」，不会建任何账号。

**`POST /api/auth/google/login`**：用 Google 账号登录已绑定 Google 的账号。

| 字段 | 必填 | 说明 |
|---|---|---|
| `id_token` | 是 | Google ID token |
| `platform_code` | 是 | 平台编码 |
| `otp_code` | 实际必填 | 发到该账号手机号的短信验证码；账号没有手机号时是发到邮箱的邮件验证码 |
| `country_code` | 校验短信时要填 | 与发送验证码时的写法相同 |
| `device_id` | 否 | 设备号 |

请求：

```json
{
  "id_token": "<Google ID token>",
  "otp_code": "123456",
  "country_code": "86",
  "platform_code": "LIVE_WEB",
  "device_id": "device-001"
}
```

响应 data：LoginResponse，见 3.1。

- 失败：`用户名或密码错误`（Google token 无效）、`Google account is not bound`、`验证码不能为空`、`验证码错误或已过期`、`邮箱验证码错误或已过期`、`用户没有可验证的联系方式`、`外部服务调用失败`；三端账号未配置 503。
- 前端流程：先用 Google 拿到 `id_token`，再引导用户给账号的手机号或邮箱发验证码（3.2），最后调本接口。

### 3.6 密码

**`PUT /api/auth/password`**（需要登录）：修改密码。

| 字段 | 必填 | 说明 |
|---|---|---|
| `old_password` | 是 | 当前密码 |
| `new_password` | 是 | 6～72 字节 |
| `otp_code` | 后端开启验证码校验时必填 | 发到账号已绑定手机号的短信验证码 |
| `country_code` | 同上 | 与发送验证码时的写法相同 |

```json
{"old_password": "secret123", "new_password": "newpass123"}
```

**`POST /api/auth/password/reset`**（不需要登录）：用验证码找回密码。

| 字段 | 必填 | 说明 |
|---|---|---|
| `account` | 否 | 要找回的账号（手机号、邮箱或登录名）；为空时依次用 `phone`、`email` |
| `phone` | 与 `email` 二选一 | 填了就校验短信验证码；必须与该账号绑定的手机号完全相同 |
| `email` | 与 `phone` 二选一 | 没填 `phone` 时校验邮件验证码；必须是该账号绑定的邮箱（不区分大小写） |
| `country_code` | 走短信时要填 | 与发送验证码时的写法相同 |
| `otp_code` | 是 | 验证码 |
| `new_password` | 是 | 6～72 字节 |

```json
{"phone": "13800138000", "country_code": "86", "otp_code": "123456", "new_password": "newpass123"}
```

**`POST /api/auth/google/password`**（需要登录）：给 Google 注册的账号设置密码，不需要旧密码。

| 字段 | 必填 | 说明 |
|---|---|---|
| `id_token` | 是 | 当前账号绑定的 Google 账号的 ID token |
| `new_password` | 是 | 6～72 字节 |

```json
{"id_token": "<Google ID token>", "new_password": "newpass123"}
```

三个接口的共同点：

- 响应 data 是新的 LoginResponse（见 3.1，`user_info.platform_code` 为 `LIVE_WEB`）。成功后旧的 `token`、`hichat_token` 全部失效，客户端要用新凭证替换本地凭证。
- `relogin_required` 为 true 时密码已经改好，但凭证为空，要让用户用新密码重新登录：

  ```json
  {
    "relogin_required": true,
    "user_info": {
      "user_id": 10001,
      "nickname": "Alice",
      "avatar": "https://cdn.example.com/avatar/10001.png",
      "phone": "13800138000",
      "email": "alice@example.com",
      "status": 1
    }
  }
  ```

  此时 `user_info` 没有 `hichat_id`、`platform_code`；读不到用户时连 `user_info` 也没有。客户端只看 `relogin_required`。
- 失败：
  - 修改密码：`旧密码错误`、`密码错误`（新密码长度不对）、`验证码错误或已过期`、`三端密码同步失败，请稍后重试`。
  - 找回密码：`用户不存在`、`验证码错误或已过期`（手机号或邮箱不属于这个账号时也是这条）、`密码错误`、`外部服务调用失败`。
  - Google 设置密码：`用户名或密码错误`（Google token 无效）、`密码错误`（新密码长度不对）、`Google identity is not bound`（账号没绑嗨聊，或三端账号未配置）、`Google identity does not belong to account`、`外部服务调用失败`。
  - 修改密码、找回密码在三端账号未配置时返回 503。

### 3.7 绑定（需要登录）

| 接口 | 请求字段（都必填） | 响应 data | 失败 |
|---|---|---|---|
| `POST /api/auth/contact/phone` | `phone`、`country_code`、`otp_code`（发到新手机号的短信验证码） | UserInfo（不带 `platform_code`） | `验证码错误或已过期`、`手机号已绑定` |
| `POST /api/auth/contact/email` | `email`（不能带显示名）、`otp_code`（发到新邮箱的邮件验证码） | `{}` | 邮箱格式不对 400；`邮箱验证码错误或已过期`、`邮箱已绑定` |

- 共同的失败：`用户不存在`、`外部服务调用失败`（写嗨聊失败）；已绑定嗨聊但三端账号未配置时 503。

绑定手机号：

```json

```

响应 data：

```json
{
  "user_id": 10001,
  "hichat_id": 20001,
  "nickname": "Alice",
  "avatar": "https://cdn.example.com/avatar/10001.png",
  "phone": "13700137000",
  "email": "alice@example.com",
  "status": 1
}
```

其他三个接口成功时响应 data 都是 `{}`。绑定邮箱的请求：

```json

```

### 3.8 注销（需要登录）

**`DELETE /api/auth/account`**

- 请求体：`password`（必填，当前密码）、`reason`（注销原因，只记录）。
- **参数放在 DELETE 请求体里**，部分代理、HTTP 库会丢弃 DELETE 的请求体，对接时先确认能传过去。
- 成功后停用嗨聊账号、软删除 Live 用户、匿名化 Discuz 账号，所有凭证失效，**不可恢复**。响应 data 是 `{}`。
- 失败：`余额未清空，暂不能注销账号`、`存在提现中的订单，暂不能注销账号`、`密码错误`、`外部服务调用失败`；已绑定嗨聊但三端账号未配置时 503。
- Google 注册且没设过密码的账号，要先用 `/api/auth/google/password` 设置密码才能注销。

```json
{"password": "secret123", "reason": "不再使用"}
```

### 3.9 积分任务（需要登录）

**`POST /api/points/task/complete`**

- 请求：`task_id`（必填，int64 数字，大于 0）。
- 响应 data：`points`（本次获得的积分）。
- 失败：`任务不存在`、`任务暂未开放`、`任务已过期`、`任务已完成`（每日任务今天已完成，或同一任务 24 小时内已提交过）、`请重新登录`（token 里没有嗨聊账号，重新登录即可）。

```json
{"task_id": 3}
```

响应 data：

```json
{"points": 10}
```

生产环境的失败响应（`sec` 是 `[]` 的密文）：

```json
{"code": -1, "msg": "密码错误", "sec": "<[] 的密文>"}
```

| 场景 | HTTP | 响应体（debug 模式） |
|---|---|---|
| 密码错误 | 200 | `{"code":-1,"msg":"密码错误","reason":"PASSWORD_INVALID","data":[]}` |
| 验证码错误 | 200 | `{"code":-1,"msg":"验证码错误或已过期","reason":"VERIFICATION_CODE_INVALID","data":[]}` |

| int64 传成字符串，如 `{"task_id":"3"}` | 400 | 同上 |

## 四、错误码

生产环境的响应里没有 `reason`，客户端按 HTTP 状态码、`code` 判断类别，按 `msg` 提示用户。`reason` 只在 debug 模式下返回，供联调排查。

| reason | HTTP | code | msg |
|---|---|---|---|
| `LOGIN_INVALID` | 200 | -700 | `未授权`（没带 token）、`Token 无效`、`Token 已失效`（改密、注销后的旧 token） |
| `PARAMS_INVALID` | 400 | -1 | `参数错误`、`旧密码和新密码不能为空` |
| `USER_NOT_FOUND` | 200 | -1 | `用户不存在` |
| `USER_ALREADY_EXISTS` | 200 | -1 | `用户已存在` |
| `USER_DISABLED` | 200 | -1 | `用户已被禁用` |
| `PASSWORD_INVALID` | 200 | -1 | `密码错误`（含新密码长度不对）、`旧密码错误` |
| `VERIFICATION_CODE_INVALID` | 200 | -1 | `验证码错误或已过期`、`邮箱验证码错误或已过期`、`验证码不能为空`、`用户没有可验证的联系方式`、`invalid verification code` |
| `INVALID_CREDENTIALS` | 200 | -1 | `用户名或密码错误`（Google ID token 无效） |
| `GOOGLE_NOT_BOUND` | 200 | -1 | `Google account is not bound` |
| `ACCOUNT_CONFLICT` | 200 | -1 | `手机号已绑定`、`邮箱已绑定`、`Google account already bound`、`Google email already registered`、`Google account already belongs to another user`、`at least one login identity is required`、`Google identity is not bound`、`Google identity does not belong to account` |
| `ACCOUNT_DELETE_REJECTED` | 200 | -1 | `余额未清空，暂不能注销账号`、`存在提现中的订单，暂不能注销账号` |
| `ACCOUNT_NOT_LINKED` | 200 | -1 | `请重新登录` |
| `TASK_NOT_FOUND` | 200 | -1 | `任务不存在` |
| `TASK_NOT_AVAILABLE` | 200 | -1 | `任务暂未开放` |
| `TASK_EXPIRED` | 200 | -1 | `任务已过期` |
| `TASK_COMPLETED` | 200 | -1 | `任务已完成` |
| `EXTERNAL_SERVICE_FAILED` | 200 | -1 | `外部服务调用失败`、`三端密码同步失败，请稍后重试`、`三端资料同步失败，请稍后重试`、`verification code already sent`、`sms disabled`、`email verification disabled`、`invalid phone`、`invalid email`、`unsupported sms country` |
| `SERVICE_UNAVAILABLE` | 503 | -1 | `Internal server error`（三端账号未配置；debug 模式下为「服务暂时不可用」） |
| `INTERNAL_ERROR`、`DATABASE_ERROR` | 500 | -1 | `Internal server error` |

reason 的定义在 `api/portal/v1/error_reason.proto`（`LOGIN_INVALID` 在 `api/common/v1`），提示语在 `internal/portal/biz/errors.go`。

## 五、openapi.yaml 怎么用

`openapi.yaml` 由 proto 生成（`make api`，或 CLAUDE.md「常用命令」里的 buf 命令），接口、字段、必填项和注释与 proto 一致。不要手改，有出入时改 proto 后重新生成。

**能直接用的**：

- **看文档、调试**：导入 Apifox、Apipost、Postman（选 OpenAPI 3），或者粘贴到 Swagger Editor、用 Redoc 预览。导入后在全局请求头里加 `Content-Type: application/json`，受保护接口加 `Authorization: hiApp <token>`。联调环境开了 debug 模式时，响应里能直接看到明文 `data`。
- **生成 TypeScript 类型**：例如 `npx openapi-typescript openapi.yaml -o src/api/portal.ts`，用生成的请求、响应类型写自己的请求封装。

**用之前要知道的**（这些 openapi 表达不出来）：

1. **响应 schema 是解密后的 data**，不是 HTTP 响应体。实际响应体是外壳 `{code, msg, sec}`，要在请求封装（如 axios 拦截器）里统一处理：`code` 为 -700 跳登录；不为 0 时提示 `msg`；为 0 时解密 `sec`（2.3）得到 data。所以不建议直接用 openapi-generator 生成的完整 SDK 发请求，它会把外壳当成 data。
2. **int64 字段在 openapi 里标为 `type: string`，实际收发都是 JSON 数字**。生成的 TypeScript 类型要把这些字段改成 `number`，请求里传字符串会返回 400。
3. **没有标注哪些接口要登录**，以 1.1 的接口清单为准。
4. **没有错误响应的定义**，错误见第四节。
5. 返回 `google.protobuf.Empty` 的接口，openapi 里响应是空内容，实际 data 是 `{}`。
6. `DELETE /api/auth/account` 带请求体，有的工具导入时会忽略它，调试时手动加上。
7. 用 openapi 起 mock 服务（Apifox mock、Prism 等）时，mock 返回的是明文 data，不是外壳，和线上不一样。

## 六、已知问题

以下是当前行为，修复需要另行确认，对接时请注意：

1. **密码请限定为 6～32 位字母加数字**（不能纯数字、纯字母，不能带符号）：本服务允许 6～72 字节的任意字符，但 Live 的邮箱登录、邮箱注册按这条规则校验，带符号的密码会导致拿不到 `live_token`。两边的统一规则还没定（X-06），前端先按 Live 的规则校验输入。
2. Live 的邮箱匹配区分大小写（与 Live 自己的行为一致），注册、登录时邮箱的大小写要保持一致。
3. `PUT /api/auth/profile` 改 `phone`、`email` 时不校验验证码、也不查重。手机号、邮箱一律走 `/api/auth/contact/*`。
4. 注册时同时填了手机号和邮箱，只按手机号查重，邮箱可能和已有账号重复。
5. Google 注册时没设密码的账号，用密码登录返回 500（不是「密码错误」），注销返回「密码错误」。这类账号先用 `/api/auth/google/password` 设置密码。
6. Google ID token 无效时提示「用户名或密码错误」。前端可以对 Google 相关接口自己换成更准确的提示。
7. `hichat_token` 由本服务直接签发，签名密钥的处理方式与嗨聊 Java 不一致（Java 先对密钥做 Base64 解码），很可能通不过嗨聊 Java 的校验；有效期也不同（Go 7 天，Java 180 天）。还没有和嗨聊联调验证。
