## 1.【运维】生产 SSR 回源的 `X-Site-Platform` 头

**现状**：按后台「SSR 回源要用 nginx 注入的 `X-Site-Platform`、缺了就失败/降级、不信客户端自塞」的规则，前端已改为——SSR 回源（`/api/preload/*` 等）的站点平台头取值优先级：
`nginx 入站头（可信）` → `环境变量 SITE_PLATFORM`（部署写死）→ 都没有则**直接失败，不静默用默认值**。

**需要你确认 / 提供**：
1. **生产环境 nginx 是否已对打到 SSR 的请求注入 `X-Site-Platform`**？（这是首选方案）
2. 若生产 SSR 不经过注入该头的 nginx，请给运维在 SSR 进程设 **环境变量 `SITE_PLATFORM=<平台值>`**（如 klive / nlive 各一套 SSR 时各自写死）。

**不这么做的后果**：生产 SSR 首屏回源会失败（按规则是「失败/降级」，不会静默带错平台）。
**怎么验**：SSR 回源请求头里 `X-Site-Platform` 为期望平台值、`/api/preload/*` 正常返回。

## 4.【bbsv2 后端】后续需登录端点的联调（提前约定）

**后续**（帖子详情/评论/收藏/通知/发帖/关注等，`member/*` 与各写接口）需要**登录态**。为提前联调，需要你：
