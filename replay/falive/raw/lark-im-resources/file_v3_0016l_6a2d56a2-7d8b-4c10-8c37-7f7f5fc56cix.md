# 个人主页「我的」列表 前端对接文档（PM-2954）

> 面向 App / H5 前端，只覆盖个人主页上的五个「我的」列表：**我的直播存档、我的帖子、我的收藏、我赞过的、我评论的**。
> 从 [bbsv2 App 对接文档](PM-2954-App对接文档.md)（社区接口全集）和
> [live 接口与业务说明 4.51 / 4.52](../live/live-接口与业务说明/04-首页配置预加载.md#m4-51)（直播回放）里摘出来，
> 补了完整的返回 JSON 示例。两边有出入时以原文档为准，并请告知后端同步本文。
>
> 示例里的 ID、昵称、地址、时间都是示意值，结构和字段跟服务端返回一致。

## 0. 一句话概览

- 「直播存档」走直播端接口 `/api/front/anchorRecordList*`；其余四个共用社区接口 `GET /bbsv2/member/threadsCursor`，用 `type` 区分。
- 四个社区列表返回同一种帖子卡片，字段见 2.1。
- 五个列表都用游标翻页（下滑加载更多）；tab 角标总数另有接口，见下表。
- 平台由服务端按登录态 / 渠道号识别，**前端不用传平台参数**，响应里也没有平台字段。

| 列表 | 下滑加载 | tab 角标总数 | 鉴权 |
|---|---|---|---|
| 我的直播存档 | `GET /api/front/anchorRecordListCursor?uid=<自己的 uid>` | `GET /api/front/anchorRecordList?uid=<自己的 uid>&page=1` 的 `total` | 公开，按直播端请求头和验签调用 |
| 我的帖子 | `GET /bbsv2/member/threadsCursor?type=posts` | `GET /bbsv2/member/threadsCount` 的 `counts.posts` | 需登录 |
| 我的收藏 | `GET /bbsv2/member/threadsCursor?type=favorite` | `counts.favorite` | 需登录 |
| 我赞过的 | `GET /bbsv2/member/threadsCursor?type=liked` | `counts.liked` | 需登录 |
| 我评论的 | `GET /bbsv2/member/threadsCursor?type=commented` | `counts.commented` | 需登录 |

## 1. 通用约定

### 1.1 鉴权与用户 ID

- 登录态跟现有 App 接口一致，请求头带 `Token`。社区接口未登录或 Token 失效返回 `code = -700`，按「去登录」处理。
- 接口里的用户 ID 一律是 **live 用户 ID**，社区、直播两边同一个值。自己的 uid 取 `GET /bbsv2/member/info` 的 `uid`，或登录用户 ID。
- 直播存档的两个接口是直播端 `/api/front/*`，请求头、验签同直播端其它公开接口；旧版 App（Android / iOS < 1.6.45）还要带
  `time`、`sign` 参数。

### 1.2 响应包体

```json
{
  "msg": "操作成功",
  "code": 0,
  "data": {},
  "sec": "<base64 加密串>"
}
```

- `code = 0` 为成功。`msg` 已按当前语言翻译（简中为「操作成功」，英文为 `Operation successful`）。
- **正式环境只有 `sec`、没有明文 `data`**，解密方式同现有直播接口（AES-128-ECB + zlib），本文示例统一按带明文 `data` 的样子展示。
- 业务错误 HTTP 状态码是 200，看 `code` 和 `msg`；非 200 的只有请求层错误（405 / 418 / 直播端验签），见第 3 节。

### 1.3 游标翻页（五个列表通用）

1. 第一页不传 `last_id`（或传 `0`）。
2. 把响应里的 `data.next_cursor` 原样作为下一次的 `last_id`。
3. `next_cursor = 0` 表示没有更多了，停止加载。

游标只用来定位，不要按它的大小判断新旧，也不要自己拼。每个列表的游标含义不同（tid、时间戳、收藏 ID 等），前端不需要关心。

### 1.4 图片可能是密文

帖子卡片里的 `picture[]`、`video[].cover` 可能是密文。显示前看文件开头 7 个字节：是 ASCII `HCIMG1` 加一个字节 `0x01`
就按 AES-256-GCM 解密后显示，否则原样显示。接口不另给标记，算法与密钥见
[bbsv2 App 对接文档 1.10](PM-2954-App对接文档.md#110-图片加密客户端按文件头解密)。

### 1.5 tab 角标：`GET /bbsv2/member/threadsCount`（需登录）

一次返回四个社区 tab 的总数，外加关注数、粉丝数。看自己时不传参数。

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| uid | int | 否 | 0 | 不传 / `0` / 自己的 uid = 看自己 |

响应 `data.counts`：

| 字段 | 类型 | 说明 |
|---|---|---|
| posts | int | 我的帖子总数：已发布（含已关闭）+ 待审核 + 未通过，不含草稿、已删除 |
| favorite | int | 我收藏的帖子数 |
| liked | int | 我赞过的帖子数 |
| commented | int | 我评论过的帖子数（按帖子计，一帖多条评论算 1） |
| following | int | 关注数（社区 + 直播按人去重） |
| follower | int | 粉丝数（社区 + 直播相加） |

**返回示例**：

```json
{
  "msg": "操作成功",
  "code": 0,
  "data": {
    "counts": { "posts": 12, "favorite": 3, "liked": 8, "commented": 5, "following": 20, "follower": 6 }
  }
}
```

直播存档的角标不在这里，取 `anchorRecordList?page=1` 的 `total`，见 2.0。

## 2. 接口详情

### 2.0 我的直播存档

直播存档就是主播的直播回放。`uid` 传自己的 live 用户 ID；只有主播有回放，普通用户调用得到空列表（不报错）。GET、POST 均可。

#### `GET /api/front/anchorRecordListCursor` — 回放列表（游标，下滑加载）

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| uid | int | 是 | 0 | 主播的 live 用户 ID，看自己传自己的 uid |
| last_id | int | 否 | 0 | 上次返回的 `next_cursor`，`0` = 第一页 |
| per_page | int | 否 | 20 | 每页条数，1~20，超过按 20 |

响应 `data`：`list[]`（字段见下方「回放字段」）+ `next_cursor`。

#### `GET /api/front/anchorRecordList` — 回放列表（分页，取角标总数）

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| uid | int | 是 | 0 | 同上 |
| page | int | 否 | 1 | 页码，从 1 起；每页固定 20 条 |

响应 `data` 是分页对象：`total`（总条数，tab 角标用它）`per_page`（固定 20）`current_page` `last_page` `data[]`（字段同下方「回放字段」）。

#### 回放字段

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 回放视频 ID |
| record_task_id | int | 录制任务 ID |
| uid | int | 主播的 live 用户 ID |
| hiChatUid | int | 主播的嗨聊 uid，可能为 `0` |
| live_id | int | 直播间 ID |
| title | string | 直播间标题。取的是直播间**当前**标题，不是录制当时的，同一主播的回放标题都一样 |
| thumb | string | 直播间封面完整地址，同样是当前封面 |
| animated_thumb | string | 动画封面（webp）完整地址，可能为空串 |
| pull | string | 回放播放地址（m3u8），带播放鉴权签名，有效期由后台配置；播不了时重新拉列表取新地址 |
| finish_time | int | 录制结束时间戳（秒），= 开始时刻 + 视频时长 |

#### 规则

- 排序：录制开始时间倒序（最新的在前），两个接口一致。
- 只列录制完成、未过期、后台没有屏蔽的回放；回放到期后自动从列表消失，`total` 也随之变小。
- 以下情况返回成功 + 空列表：取不到渠道号、`uid` 未传或 ≤ 0、主播对当前平台不可见。
- 游标对应的回放在翻页过程中被删除时，下一页返回空列表，按「已到底」处理；下拉刷新重新从第一页取。

### 2.1 我的帖子

「我的帖子」是作者本人视角：返回已发布（含被后台关闭的）+ 待审核 + 未通过的帖子，按发帖先后倒序；草稿和已删除的不在里面。

#### `GET /bbsv2/member/threadsCursor?type=posts`（需登录）

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| type | string | 否 | posts | 传 `posts` |
| last_id | int | 否 | 0 | 上次返回的 `next_cursor`，`0` = 第一页 |
| per_page | int | 否 | 10 | 每页条数，1~50，超过按 50 |
| audit_status | int | 否 | 0 | 状态筛选：`0` 全部 · `1` 已发布 · `2` 待审核 · `3` 未通过。页面「全部 / 已发布 / 审核中 / 未通过」切换直接传 |

响应 `data`：`list[]`（帖子卡片，字段见下表）+ `next_cursor`。

- 卡片的 `audit_status` 用来显示状态角标；`closed = 1` 是被后台关闭的帖子，只有作者本人看得到。
- 点卡片进 `GET /bbsv2/thread/detail?tid=`。待审核 / 未通过 / 已关闭的帖子作者本人能正常看详情，详情也带 `audit_status`。
- 草稿箱另走 `GET /bbsv2/thread/listCursor?type=2`。
- tab 角标：`member/threadsCount` 的 `counts.posts`，等于 `audit_status = 0` 的列表总数。
- 下拉刷新提示「有 N 条新内容」：`GET /bbsv2/member/threadsNewCount?type=posts&since_id=<最上面一条的 tid>&audit_status=<与列表相同>`。

#### 帖子卡片字段（四个社区列表共用）

| 字段 | 类型 | 说明 |
|---|---|---|
| tid | int | 帖子 ID，跳详情用 |
| fid / typeid | int | 版块（圈子）ID / 分类 ID |
| subject | string | 标题 |
| author | object | `uid`（live 用户 ID）`nickname` `avatar` `groupid` `group_title`（用户组名） |
| authorid | int | 作者 live 用户 ID，同 `author.uid`；为 `0` 时头像、昵称不可点 |
| dateline | int | 发帖时间戳（秒） |
| views / replies / heats / recommend | int | 浏览数 / 回复数 / 热度 / 点赞数 |
| digest | int | `0` 非精华，`> 0` 显示「精华」角标 |
| closed | int | `1` = 已被后台关闭，只会在「我的帖子」里出现 |
| displayorder | int | 原始显示序，前端不用，状态看 `audit_status` |
| audit_status | int | `1` 已发布 · `2` 待审核 · `3` 未通过。只有「我的帖子」会出现 `2` / `3`，其余三个列表恒为 `1` |
| mediatype | int | `1` 纯文字 · `2` 图片 · `3` 视频 |
| forum_name | string | 版块（圈子）名 |
| message | string | 正文纯文本，已去掉图片视频标记，换行合并为空格，不截断 |
| tags | string[] | 标签名 |
| picture | string[] | 图片地址，有缩略图的直接给缩略图；可能是密文（见 1.4） |
| video | object[] | 每项 `cover`（封面，可能是密文或空串）`video`（播放地址）`duration`（毫秒，可能为 `0`，为 0 时不显示时长） |
| url | string | 详情页地址 |
| is_liked | int | 我是否已点赞：`1` 是 · `0` 否 |
| is_favorited | int | 我是否已收藏：`1` 是 · `0` 否 |
| last_comment | object \| null | 只有「我评论的」有值，见 2.4；其余列表恒为 `null` |

### 2.2 我的收藏

返回我收藏的帖子卡片，按收藏先后倒序（最近收藏的在前）；同一帖收藏过多次只出现一张卡片。

#### `GET /bbsv2/member/threadsCursor?type=favorite`（需登录）

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| type | string | 是 | posts | 传 `favorite`（不传会变成「我的帖子」） |
| last_id | int | 否 | 0 | 上次返回的 `next_cursor`，`0` = 第一页 |
| per_page | int | 否 | 10 | 每页条数，1~50 |

响应 `data`：`list[]`（帖子卡片，字段同 2.1，`is_favorited` 恒为 `1`，`last_comment` 为 `null`）+ `next_cursor`。

- 只列当前平台可见、已发布且未关闭的帖子。帖子被删除 / 关闭 / 下架后不再出现，角标也不计。
- 只有帖子收藏，不含版块收藏。
- 取消收藏：`POST /bbsv2/favorite/remove`，传 `tid` 即可（卡片上没有 `favid`）；成功后前端直接把卡片移掉、角标减 1。
- tab 角标：`member/threadsCount` 的 `counts.favorite`。
- 下拉刷新：直接重拉第一页。这个列表的游标是收藏 ID，卡片里没有，前端拿不到最上面一条的游标，`threadsNewCount` 在这里用不了。

### 2.4 我评论的

按帖子出卡片，一帖评论多次只出一张，按我最后一次评论该帖的时间倒序；每张卡片额外带 `last_comment`（我在这帖下最新的一条评论）。

#### `GET /bbsv2/member/threadsCursor?type=commented`（需登录）

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| type | string | 是 | posts | 传 `commented` |
| last_id | int | 否 | 0 | 上次返回的 `next_cursor`，`0` = 第一页 |
| per_page | int | 否 | 10 | 每页条数，1~50 |

响应 `data`：`list[]`（帖子卡片 + `last_comment`）+ `next_cursor`。

#### `last_comment` 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| pid | int | 评论 ID，跳详情时作 `comment_id` 传 |
| message | string | 评论内容摘要（纯文本） |
| dateline | int | 评论时间戳（秒） |
| recommend | int | 这条评论的点赞数 |
| position | int | 楼层号，详情页定位用 |
| reply_to_pid | int | 被回复的评论 ID；`0` = 直接评论帖子 |
| reply_to_author | string | 被回复评论的作者名（取社区帖子表里记的名字，可能跟别处显示的直播昵称不同）；`reply_to_pid = 0` 时为空串 |
| reply_to_message | string | 被回复评论的内容摘要；`reply_to_pid = 0` 时为空串 |

- 只算正常显示的楼层回复：发帖时的首楼不算，待审核 / 已删除的评论不算；在自己帖子下的回复也算。帖子本身须已发布且未关闭。
- 点卡片：`GET /bbsv2/thread/detail?tid=<tid>&comment_id=<last_comment.pid>`，响应里的 `my_comment` 用来显示「你的评论」卡片；
  用 `last_comment.position` 定位楼层。
- tab 角标：`member/threadsCount` 的 `counts.commented`（按帖子计）。
- 下拉刷新提示：`GET /bbsv2/member/threadsNewCount?type=commented&since_id=<最上面一张卡片的 last_comment.dateline>`。

## 3. 错误码与错误返回

`msg` 已按当前语言翻译，下表括号里是服务端的文案 key，示例按简中展示。

| 场景 | HTTP | code | msg（简中） | 前端处理 |
|---|---|---|---|---|
| 未登录 / Token 失效（社区四个列表） | 200 | -700 | 登陆状态失效，无TOKEN | 跳登录或刷新 Token |
| 自己的社区账号还没开通成功 | 200 | -1 | 用户不存在（`BBSV2_USER_NOT_EXIST`） | 提示稍后再试；心跳 `GET /bbsv2/index/index` 会自动开通 |
| `type` 不是 posts / favorite / liked / commented | 200 | -1 | 我的帖子类型无效（`BBSV2_MEMBER_THREAD_TYPE_INVALID`） | 修正传参 |
| `type=posts` 时 `audit_status` 不在 0~3 | 200 | -1 | 帖子状态筛选无效（`BBSV2_MEMBER_AUDIT_STATUS_INVALID`） | 修正传参 |
| 社区列表用了 POST | 405 | -1 | 请求方式错误，请使用 GET（`BBSV2_HTTP_METHOD_NOT_ALLOWED`） | 列表只接受 GET |
| 数字参数传了非数字、单值参数传了数组 | 418 | -1 | 开发排查用的中文说明，未翻译 | 修正传参，`msg` 不要展示给用户 |
| 直播存档：签名错误 | 407 | -800 | Invalid request | 检查直播端验签 |
| 直播存档：客户端时间超窗 | 402 | -888 | local time error | 按响应头的服务器时间校时后重试 |

**未登录**：

```json
{ "msg": "登陆状态失效，无TOKEN", "code": -700, "data": [] }
```

**社区账号还没开通**：

```json
{ "msg": "用户不存在", "code": -1, "data": [] }
```

**`type` 无效**（如 `type=draft`）：

```json
{ "msg": "我的帖子类型无效", "code": -1, "data": [] }
```

**`audit_status` 无效**（如 `type=posts&audit_status=4`）：

```json
{ "msg": "帖子状态筛选无效", "code": -1, "data": [] }
```

**请求方式错误**（HTTP 405，响应头 `Allow: GET`）：

```json
{ "msg": "请求方式错误，请使用 GET", "code": -1, "data": [] }
```

**参数错误**（HTTP 418，如 `last_id=abc`；包体是明文，不走 `sec` 加密）：

```json
{ "code": -1, "data": [], "msg": "app\\http\\bbsv2\\ctrl\\CMember::threadsCursor 参数 类型错误(应为数字), 请客户端协调检查：last_id - ExceptionCode:0" }
```

## 4. 注意事项

- 帖子被删除、被后台关闭或下架后，不再出现在「收藏 / 赞过 / 评论的」里，角标同步减少。
- 「我的帖子」里被删除的不出现，被下架的显示为 `audit_status = 3`（未通过），被关闭的带 `closed = 1`。
- 直播回放过期后从列表里消失。
- 社区四个列表只算当前平台的帖子。
- 这些社区接口只能看自己。他人主页：帖子用 `GET /bbsv2/thread/listCursor?type=1&uid=`（只有已发布），角标用
  `member/threadsCount?uid=`；他人的收藏 / 赞过 / 评论的不对外，计数恒为 `0`。直播存档传对方的 `uid` 即可看他人。
- 需要跳页时，社区四个列表另有分页版 `GET /bbsv2/member/threads`（`page` + `per_page`，参数与口径同游标版，响应最外层多一个
  `page` 对象），见 [bbsv2 App 对接文档 2.6](PM-2954-App对接文档.md)。
