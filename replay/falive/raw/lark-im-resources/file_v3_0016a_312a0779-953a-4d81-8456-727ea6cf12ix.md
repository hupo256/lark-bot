### 后端答复（按代码核对，2026-10-09）

**1. `banner_type` 固定传 `1`。** 后台保存轮播图时一律把类型写成 1（APP 轮播图），没有其它分类，0、2~10 永远是空。值与站点 / 渠道无关。

**2. 访客态拿到空数组，根因不在 `banner_type`，在「平台」。** 服务端按（平台 + 语言 + 类型）查，三者都要对上：

| 维度 | `/api/banner/getBannerList` 怎么取 | 对不上的后果 |
|---|---|---|
| 平台 | **只看 `token` 里的平台**，不看 `x-site-platform`、`channel_code` | 没带 `token` → 平台为 0 → 一定为空（轮播图没有平台 0 的数据） |
| 语言 | 请求头 `x-accept-language`（其次 `Accept-Language`、语言 Cookie），都没有时为 `zh-cn` | 该平台没配这个语言的轮播图 → 空 |
| 类型 | `banner_type` | 不是 1 → 空 |

- **游客 `token` 怎么拿**：请求没带游客 ID（`b2b-Visitor` 头）或对不上时，服务端会在**响应头**里下发 `b2b-Visitor`（游客 ID）和 `b2b-Visitor-Token`（游客 token，已按渠道写入平台）；之后把它放进 `token` 请求头即可。登录后用登录接口返回的 `data.token`，同样带平台。
  - 注意：php 代码没有设置 `Access-Control-Expose-Headers`，浏览器跨域时能否读到这两个响应头取决于 nginx 配置，读不到请找运维放行。
  - `token` 里的平台和请求渠道对不上（或平台为 0）时，服务端返回登录失效（code 绝对值 700），前端需重新获取 token。
- **或者首页轮播图直接改用预加载版 `/api/preload/getBannerList`**：参数与返回完全相同，但平台按渠道取（请求头 `b2b-channel: hc`，或参数 `channel_code=hc`），不依赖 `token`，游客态、登录态都能用。

**3. pre 是否有数据**：代码层面答不了，需运维在 pre 直播库查轮播图表（b2b 为 `cmf_banner_b2b`）里 `type=1 AND status=1` 的记录，按 `platform_id`、`lang` 看 `hc` 所属平台、前端所用语言下有没有数据。

#### 请求参数

两个端点参数相同，GET / POST 均可，需 vn-sign。

| 参数 / 请求头 | 类型 | 必填 | 说明 |
|---|---|---|---|

| `x-accept-language` 头 | string | 否 | 决定返回哪种语言的轮播图（见下表），不传为 `zh-cn` |

### 开播流程里的 ID 关系

```
getLiveUrl  → 返回 { url(推流地址), id }   ← 生成一条 islive=-1（创建中）的直播记录
createRoom(id, type, title, thumb, …)       ← id 必须是上一步的 id；成功后该记录 islive=0（未直播）
getRoomList                                 ← 此时能列出该记录（islive=-1 的不列）
startRoom(id)  /  endRoom(id)               ← id = getRoomList 的 data[].id（直播记录 ID）
getRoomInfo(uid)                            ← 注意入参是「主播用户 ID」，不是直播记录 ID
```

### A.2 `GET|POST /api/li_stre/getRoomInfo` — 直播间信息（观众 / 主播通用）

**鉴权**：公开，游客可调。服务端须能从请求解析出渠道（`x-site-platform` / 渠道参数），解析不到时成功但 `data` 为空。

**请求参数**

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| uid | int | 是 | 0 | **主播用户 ID**（不是直播记录 ID）；传 0 → `Parameter error` |
| videoType | string | 否 | `""` | 播放器能力：`m3u8` / `flv`；不传按终端判断（H5 给 m3u8）。**web 建议传 `m3u8`** |
| ttl | int | 否 | 30 | 服务端缓存秒数，前端不要传（`-1` 是强刷，仅后台排查用） |

**WebSocket 订阅用的 `vid`：取顶层 `data.vid`**。未开播时也有值（32 位大写 md5）；`data.info.vid` 在主播没有「直播中 / 已关播」记录时为 `null`，不要用它。
`vid` 按直播记录生成，**每场直播不同**：未开播时拿到的是上一场（或按主播 ID 推算）的房间号，主播开播后应重新调一次 getRoomInfo 换成新 `vid` 再订阅。

**响应 `data` 顶层**

| 字段 | 类型 | 说明 |
|---|---|---|
| `info` | object | 直播间信息，见下；结构随**是否直播中**不同 |
| `vid` | string | 聊天室房间号（WebSocket `sub` 用这个） |
| `userData` | object | 主播信息，见下；结构随是否直播中不同 |
| `reserve` | object \| `[]` | 下一场预约；**只有直播中且有未来预约时**才是对象，否则 `[]` |
| `chat_msg_close` | int | 聊天模式：0 全开 / 1 只显示主播消息（未开播时恒 0） |
| `country` | string | 访问者国家代码 |
| `block` | bool | 遗留，当前恒为 `false`；判断「地区限制」请用 `info.isLoop` |

- `servertime`、`isLoop`、`isRecord`、`tags`、`pull_m3u8`、`pull_flv` 照常有（地址为空）。

## 附 B：WebSocket（直播间）消息体

> 来源：php 文档页 `/doc/liveDoc` 的「ws 各情境消息状态」各节（`app/http/doc/view/livedoc/base.phtml`）。开播 / 关播两条推送已对照 php 发送代码核对；其余为文档示例，发送端在独立的 chat 服务，未逐条核对。
> 下面只列 web 观众端直播间会用到的；私聊 / 群组（`noticeUser` 的 `send` / `newMsg` / `newRoom` / `kickuser` / `pin` 等）见 `/doc/liveDoc` 对应章节。

### 连接流程

1. 调 `/api/chat/getChatToken`（公开，游客也可）拿 `data.token`（聊天凭证，**不是**登录 token）。
2. 连 `wss://{聊天服务域名}/wss/?userToken={聊天凭证}`。域名由运维提供（前端 `service-hosts.ts` 里的 `chat` host）。连上后服务端先推 `{"action":"open", "fd":…, "info":{userId, userType(0 游客/1 用户), channelCode, vid, …}}`。
3. 心跳：每 10 秒发一次字符串 `"heart"`。
4. 进直播间发 `{"action":"sub","vid":"<getRoomInfo 顶层 data.vid>"}`，成功回 `{"action":"response","code":0,"msg":"SUCCESS-SUB-<vid>"}`；离开发 `{"action":"unsub","vid":"…"}`。**只有订阅了的房间才收得到 `method=notice` 的消息。**

所有推送都带 `method`（分发通道）、`action`（动作）、`prefix`（平台）、多数带 `seed`（唯一串，用于去重）。按 `method + action` 分发处理。

### 直播间相关推送

| method / action | 场景 | 关键字段 |
|---|---|---|
| `notice` / `send` | 直播间公屏消息（用户 / 机器人 / 管理员发言、贴图） | `msg_id`、`vid`、`text`、`msg_type`（0 弹幕 / 1 文字 / 2 图片 / 3 图文）、`pic`（贴图地址）、`sender`、`sender_user_type`（0 游客 / 1 管理员 / 2 会员）、`sender_nickname`、`avatar`、`sender_exp`（等级）、`designation` / `designation_color`（头衔）、`time` / `time_ms`、`seed`。机器人消息另有 `sender_avatar`、`comment`、`room_type` |
| `notice` / `gift` | 直播间送礼 | `vid`、`gift_id`（字符串，对照礼物列表接口取图 / 名称）、`sender_nickname`、`sender_exp`、`sender_user_type`、`seed` |
| `notice` / `ban` | 管理员禁言某用户 | `vid`、`room_type`（0 直播间）、`userid`（被禁言者；等于自己时禁用输入框）、`seed` |
| `notice` / `delmsg` | 管理员删除一条消息 | `vid`、`room_type`（0）、`msg_id`、`msg_seed`、`seed`；按 `msg_id` 从公屏移除 |
| `notice` / `clearHistory` | 管理员一键清屏 | `vid`、`room_type`（0）；清空该房间公屏 |
| `noticeAll` / `closeLive` | 关播（**全平台广播**） | `vid`、`userid`（**关播主播 ID**）、`seed`；`vid` 等于当前房间时切到「已关播」状态 |
| `noticeUser` / `startLive` | 你关注的主播开播（**只推给该主播的粉丝**，需登录） | `userid`（**开播主播 ID**）、`filiterUserType`（恒 2）；收到后可调 getRoomInfo(uid=userid) 拿新 `vid` |
| `noticeChannelsByDay` / `send` | 直播间聊天公告 / 跑马灯 | `title`、`text`、`pic`、`link`、`msg_type`（3 图文）、`ad`（1 渠道公告 / 2 跑马灯 / 3 渠道聊天广告 / 4 更新公告）、`day`（满足登录天数才显示）、`im_user_group`（0 全部 / 1 前台游客 + 用户 / 3 仅游客 / 4 仅用户）、`vid` |
| `noticeUser` / `reserveStartLive` | 预约的节目开始了 | `text` 为节目对象：`id`、`title`、`thumb`（相对路径）、`starttime`、`endtime`、`lang` 等 |

**`/doc/liveDoc` 清单里有、但没有消息体示例的直播间 action**：`notice/system`（进房消息）、`notice/inRoom`（满级 / 大户进房特效）、`notice/redbag` / `redbagOn`（红包）、`noticeAll/toggle`（切播事件）。web 观众端若要做这几项，再找后端补。
