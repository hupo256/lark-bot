## 一、pre 现在就要做（影响今天的验收）

### 1. pre 前端没有部署最新代码

- `https://falivepre.fdsser.com` 跑的还是 10-08 之前的旧包：首页、`/news`、`/lives`、`/room/133` 都是 HTTP 500，`/download` 是 404。


- 部署后如果仍然 500，请把 SSR 服务的日志发我们。多半是回源问题：出口 IP 白名单、`X-Site-Platform` 头、服务器时钟。

### 3. 直播拉流 403（一期核心，直播间看不了视频）

播放域名 `play2zz.sysiyu11.com` 的腾讯云配置。live 后端说这不是代码问题，已转给运维。请逐项核对：

1. **Referer 防盗链白名单加上 `falivepre.fdsser.com`**，以及各环境的正式前端域名；本地开发要的话加 `localhost`。前端实测就是卡在这里：Referer 是其他域名时 403，不带 Referer 时鉴权能过。
2. 控制台的「鉴权有效时间」：后端两份答复一个说 5 分钟、一个说 10 分钟，0 不行。
3. 后台「平台管理 → 直播配置」的拉流 key，要和控制台的主 / 备 KEY 一致。
4. 有没有地区或 IP 访问限制。

另外请在 pre 安排一路真实推流用于验收。改好后告诉前端实际有效期，我们复测。

### 4. 后台「静态资源地址」改成 https

- 现在配的是 `http://streampre.fdsser.com`，接口返回的图片都是 `http://`，在 https 页面上会混合内容。
- 已实测 `https://streampre.fdsser.com/upload/...` 可以访问，证书正常，直接改配置即可。
- uat / online 上线前同样检查。

### 5. SSR 服务器开 NTP 校时

服务器时间和 php 相差超过约 ±60 秒时，php 返回 HTTP 402，首屏会全部失败。

## 二、要提供的信息

| # | 要什么 | 用途 |
|---|---|---|
| 6 | **pre / uat / online 的 SSR 服务器出口 IP** | online 的出口 IP 要加 php 白名单（pre / uat 已加）。php 限流是同一 IP 超过 28 次 / 秒就整个 IP 拦截，所有用户的 SSR 请求都从一个出口 IP 发出，很容易撞上。live 后端建议给 SSR 出口 IP 做免限流配置，需要这些 IP |
| 7 | **uat / online 的聊天 WebSocket 域名** | pre 是 `falivepre.fdsser.com`，已通 |
| 8 | **各环境的前端访问域名** | SEO（canonical、sitemap、og:url）和后端的跨域白名单 |
| 9 | **online 的站点平台和渠道码是不是 `hc`** | nginx 转发到 SSR 时注入 `X-Site-Platform: hc`，或者给 SSR 进程设环境变量 `SITE_PLATFORM` |

## 三、uat / online 上线前

### 10. 主域名 nginx 配齐反代表

| 同源前缀 | 转发到 | 备注 |
|---|---|---|
| `/api/`、`/bbs/`、`/discuz`、`/upload` | php | `/bbs/` 要带末尾斜杠，否则会把 `/bbsv2` 吞掉 |
| `/wss` | 聊天 WebSocket 域名（第 7 条） | 需要透传 `Upgrade` / `Connection` 头 |
| `/bbsv2/` | php，和 `/api/` 同一个端口，路径不改写 | 配置见下 |
| `/hc-api` | hichat：uat `https://uat-hailiao.hai-liao-uat.com`，online `https://www.4ees1.xyz` | 去掉 `/hc-api` 前缀 |
| 其他所有路径 | Node SSR 服务 | 包括页面和 `/assets/*` |

社区后端给的 `/bbsv2/` 配置（主域名模板里已有 `client_max_body_size 50m`）：

```nginx
location ^~ /bbsv2/ {
    proxy_pass http://127.0.0.1:8068;   # swoole，和 /api/ 同一个端口，路径不改写
    proxy_set_header X-Forwarded-Host  $http_host;
    proxy_set_header x-forwarded-for   $remote_addr;
    proxy_set_header REQUEST_SCHEME    $scheme;
}
```
