## P0

### B1 uat / online 域名 —— 需运维

- bbsv2 不是独立服务，而是 php 里的一个模块，和 `/api` 跑在同一个进程里。php 发到 uat / online 后 bbsv2 就有了，不需要单独部署。
- 现在缺的是 nginx 把 `/bbsv2/` 转给 php（见 B2）和对外域名。请找运维要，可以和对接-04 O4（WS 域名）一起提。
- 拿到域名之前，前端显示「加载失败」、不显示假帖子，这样处理没有问题。

### B2 路径与 host —— 同级路径、同一个服务

- `/api/*` 和 `/bbsv2/*` 转给同一个 php 端口：`/api/` 由 nginx 改写成 `/live/` 再转发，`/bbsv2/` 原样转发。两者的验签、`sec` 加密、渠道头、错误码规则完全相同。
- pre 要用独立的 admin host，原因是前台主域名的 nginx 只把 `/api/` 转给 php，其余路径都转给前端 Node（3000 端口），没有配 `/bbsv2/`。所以在主域名上请求 `/bbsv2/`，会打到前端 Node 自己。
- **建议**：uat / online 在前台主域名的 nginx 加一段 `/bbsv2/` 转发，pre 也建议顺手补上。这样前端的 `/api` 和 `/bbsv2` 用同一个 host，不用单独配社区 host，也没有跨域问题。php 侧的 bbsv2 只在 debug 环境给几个 demo 域名开了跨域 GET。如果用独立 host，浏览器直连会被跨域拦掉，除非前端经自己的 Node 转发。

  ```nginx
  location ^~ /bbsv2/ {
      proxy_pass http://127.0.0.1:8068;   # swoole，和 /api/ 同一个端口，路径不改写
      proxy_set_header X-Forwarded-Host  $http_host;
      proxy_set_header x-forwarded-for   $remote_addr;
      proxy_set_header REQUEST_SCHEME    $scheme;
  }
  ```

  主域名的 nginx 模板里已经有 `client_max_body_size 50m`，这是给 bbsv2 上传视频准备的，所以只需要补这一段 location。

## P1

### B3 「关注」 「推荐」 「热门」信息流 —— 没有，产品确认暂不做

### B6 分类 chip 行 —— 有（用标签）

- bbsv2 没有单独的「分类字典」接口。社区里能当分类用的是**标签**，建议 chip 行直接用标签：
  - chip 数据：`GET /bbsv2/forum/allTags`，返回全部标签（`tagid` + `name`，按 `tagid` 升序）；也可以用 `forum/hotTags?limit=14`，按当前平台的使用次数降序。
  - 筛选：`thread/listCursor?tag_id=<tagid>`，`preload/threadListCursor` 也支持这个参数，已经可以用。
  - 多语言：标签名已按请求语言返回。译名由后台维护，没有译名的语言显示简中原文。
  - 这 14 个分类由运营在社区后台的标签管理里维护，状态为「开放」的标签才会返回。
- **不建议**用版块 `fid` 或版块分类 `thread_types`：发帖接口不接收版块和分类参数，新帖都落在平台的第一个版块、`typeid=0`，按这两个条件基本筛不出东西；`listCursor` 也没有 `typeid` 参数。
- **缺口**：标签没有「运营排序」字段。如果设计稿要求 14 个 chip 按固定顺序展示，需要我们给标签加排序字段（会做，排期待定）；不要求的话，前端先按 `hotTags`（热度）或 `allTags`（`tagid`）的顺序展示。

### B7 收藏 —— 有

以下接口都需要登录（请求头 `Token`），详见文档 2.7：

| 动作 | 接口 | 参数 |
|---|---|---|
| 收藏 | `POST /bbsv2/favorite/add` | `id=<tid>`、`idtype=tid`，`title` 可以不传 |
| 取消 | `POST /bbsv2/favorite/remove` | `favid` 或 `tid` 二选一 |
| 我的收藏 | `GET /bbsv2/favorite/listCursor` | `last_id` / `per_page` |

注意：帖子列表项（`listCursor` / `hot` / `recommend`）**不带**收藏和点赞状态，只有 `thread/detail` 返回 `is_favorited` / `favid` / `is_liked`。所以一期列表卡片上的图标只能先显示「未收藏」，用户点了以后以接口返回为准。如果要在列表上直接显示已收藏、已点赞，需要我们给列表项加字段（需要评估，排期待定）。

### B8 帖子分享 —— 不能直接分享 `url`

- 列表项里的 `url` 是旧 Discuz PC 站的地址：`<Discuz PC 域名>/forum.php?mod=viewthread&tid=N`，域名取自后台的多域名配置，不是 Falive Web 的页面。文档示例里的 `https://x9.example.com/bbs/thread/N` 只是示意。
- 建议前端做帖子详情页，分享链接用前端自己的路由加上 `tid` 拼出来：
  - 浏览器里取数据用 `thread/detail`；
  - SSR 或分享落地页用 `preload/threadDetail`：免验签、返回明文，带 `tdk`，可以直接填 `<title>` 和 `<meta>`；
  - 帖子不存在时 `code` 固定为 `-3`，可以据此返回 404 页。
- 前端定好详情页路由后告诉我们，可以把 `url` 改成指向 Web 详情页，后续 App 分享也能直接用。

## P2

### B9 用哪个 token —— live 的 `data.token`

- 用 live 登录（`NewLogin` 等）返回的 `data.token`，和 `/api` 是同一套：请求头 `Token: <token>`。不用 hichat JWT，bbsv2 也没有自己的 token。
- 需要登录的接口没带 token 或 token 已失效时，返回 `code=-700`，和 live 一样处理。
- 登录后建议先带 `Token` 调一次心跳 `GET /bbsv2/index/index`。服务端会当场开通或认领社区账号，并同步昵称和头像；`community.state` 为 `ready` 或 `created` 就可以用了。不调也没关系，第一次调用需要社区账号的接口时，服务端也会自动开通。

### B10 用户资料是否要从旧 discuz 迁到 bbsv2 —— 不用迁

- bbsv2 本身就跑在 Discuz 的库表上，以下接口已经可以用，前端直接调 bbsv2 的接口，不要再接旧 discuz 的页面或接口：
  - `GET /bbsv2/member/info`：我的资料
  - `member/otherInfo`：他人主页
  - `member/threadsCount`：主页各 tab 的条数，以及关注数和粉丝数
- 昵称和头像以 live 为准：用户在 live 改了资料后，下次心跳时社区资料会自动同步。
- 注意 bbsv2 里的 `uid` 是社区 uid（Discuz uid），**不等于** live 用户 id。跳转直播间请用返回里的 `live.anchor_id`。
